## 从想法走向可用结果

ChatGPT 是一个可以用自然语言交流的 AI 智能体：

## 选择工作方式

需要提问或来回交流时，使用 Chat。希望把较大的任务推进到可评审结果时，请在切换器中开启 Work。需要开发者视图或更多技术细节，尤其是处理软件开发时，选择 Codex。

<div className="doc-table-wrap">

| 选择 | 适合的目标 | 示例 |
| --- | --- | --- |
| Chat | 与 ChatGPT 一起梳理问题 | 提问、搜索 Web、头脑风暴、起草消息、比较选项 |
| ChatGPT Work | 定义结果并获得可评审交付物 | 创建演示文稿、分析文件、起草报告、制定项目计划 |
| Codex | 使用开发者工具并查看技术细节 | 调试代码、运行测试、评审 PR、实现功能 |

</div>

可以用 Chat 提问、头脑风暴、起草或修改文字、总结文件、比较选项，或澄清一个更大的任务。在 Codex 中，把鼠标指向 **New chat（新建聊天）**；当 **Quick chat** 可用时，选择它即可开始普通 ChatGPT 聊天。

需要完整且可评审的结果时，请切换到 **Work**，并说明结果需要包含什么。示例任务、提示词和最佳实践见[开始使用 ChatGPT Work](/docs/get-started-with-work)。

### ChatGPT Work 可以做什么

ChatGPT Work 可以规划任务、收集上下文、使用工具，并把工作推进到可供你评审的结果。

<Screenshot
  src="/images/codex/get-started-with-work/comparison-spreadsheet.webp"
  alt="ChatGPT Work 在电子表格中比较供应商"
  width={1540}
  height={988}
/>

你可以让它：

- **研究并分析信息。** 搜索 Web、浏览网站、比较来源、读取文件、分析数据并总结发现。
- **使用你的文件和工具。** 引入上传的文件、[项目](/docs/projects)、记忆、ChatGPT Library 和已安装的 [plugins](/docs/plugins)。Plugins 可以提供已连接的信息、可复用工作流和受支持的操作。
- **创建完整文件。** 起草并完善[文档、演示文稿、电子表格和 PDF](/docs/artifacts-viewer)。评审结果、提出具体修改要求，再下载完成的文件。
- **创建视觉与交互式成果。** 生成或编辑[图片](/docs/image-generation)，制作交互式[可视化](/docs/visualizations)，并使用 [Sites](/docs/sites) 构建或分享网站和 App。
- **跨网站和 App 工作。** 使用 [Browser](/docs/browser) 研究网站并与之交互。在桌面 App 中，还可以在相关能力可用时使用 [Chrome extension](/docs/chrome-extension)、[Computer Use](/docs/computer-use) 和 [appshots](/docs/appshots)。
- **运行代码并评审技术工作。** 运行代码和 shell 命令、分析数据、检查文件、[评审代码](/docs/code-review)，并操作所选环境可以访问的仓库。
- **委派并继续较长任务。** 把独立工作拆给[子智能体](/docs/agent-configuration/subagents)，跟踪进度，并让[长时间运行的工作](/docs/long-running-work)持续执行。
- **重复有用的工作流。** 为重复工作设置[计划任务](/docs/automations)，并使用 [skills](/docs/skills-and-plugins) 复用工作流。
- **通过语音讨论任务。** 在桌面 App 的受支持套餐中，使用 [ChatGPT Voice](/docs/features/voice) 开始工作、检查进度或调整方向。

<Note>

功能是否可用取决于套餐、平台、地区、灰度发布和工作区设置。工作区管理员可以控制 ChatGPT Work、plugins、浏览器使用和网络访问权限。ChatGPT Work 与 Codex 共享[用量限制](/docs/pricing)。

</Note>

### 选择云端或本地工作

在 Web 上，ChatGPT Work 会在托管云端环境中运行。在桌面 App 中，你也可能可以选择任务的运行位置：

- **Cloud（云端）：** 在隔离的托管环境中运行工作。关闭桌面 App 后，任务仍可继续，并能从 Web 或移动 App 接着处理。云端工作可以使用上传的文件、已连接工具和已批准的网站。
- **Work locally（本地工作）：** 使用电脑上的文件、App 或浏览器。当你的账号或工作区启用该能力时，可以在桌面 App 中使用本地工作。

ChatGPT 会显示进度，并在需要信息或批准时暂停。批准有重要后果的操作前应先评审，并在使用或分享最终结果前完成检查。

### 比较桌面端的 ChatGPT Work 与 Codex

ChatGPT Work 与 Codex 的能力存在重叠。如果更喜欢 Codex，你可以继续用它完成研究、文档、演示文稿和其他知识工作。当两个入口都可用时，桌面 App 主要会改变界面以及智能体展示工作的方式。

<Toggle summary="详细比较">

<div className="doc-table-wrap">

| 差异 | 桌面 App 中的 ChatGPT | 桌面 App 中的 Codex |
| --- | --- | --- |
| 从哪里开始 | 选择 **ChatGPT**，再把输入框切换到 **Work** | 在产品选择器中选择 **Codex** |
| 可见聊天 | 查看从 Web 和移动端使用 Chat 发起的聊天，以及 ChatGPT Work 聊天 | 聚焦 Codex 聊天和开发项目 |
| Quick chat | 不可用 | 功能可用时，可在 Codex 中访问来自 Web 和移动端的 ChatGPT 聊天 |
| 技术细节 | 隐藏 Git 或 shell 命令等技术细节 | 显示开发者细节，包括 diff 和评审视图 |
| 智能体表达 | 偏向非技术语言和完成后的产出 | 可以包含技术与实现细节 |
| Pull requests 面板 | 使用 ChatGPT Work 时不可用 | 启用后可用 |

</div>

</Toggle>

### 用自然语言与 ChatGPT 交流

像向一位乐于帮忙的同事说明请求一样写提示词。先说清希望实现什么，再补充会影响答案的细节和所需格式。第一条提示词只是起点，你可以通过后续消息添加上下文或继续完善结果。

<ChatComposer
  caption="向 ChatGPT 发送消息"
  options={["先从简单要求开始", "再补充上下文", "最后指定格式"]}
  prompt="Help me plan a 30-minute team meeting about our new customer feedback process."

你可以用下面这样简单的指令继续：

- “Make this shorter.”
- “Give me three different approaches.”
- “What assumptions are you making?”
- “Ask me questions before you continue.”

进一步了解[提示词](/docs/prompting)，或参加 [AI Foundations 课程](https://academy.openai.com/home/courses/ai-foundations-juzjs)进行引导式练习。

## 为 ChatGPT 提供合适的上下文

提供与任务有关的信息、工具和指令。你不需要给出所有内容，只要加入会改变优质结果标准的上下文。

### 把相关工作放在一个项目中

项目可以围绕主题、目标或持续工作组织 ChatGPT。当工作会长期继续，或依赖同一套上下文时，把相关聊天、文件和指令放在同一个项目中。[进一步了解项目](/docs/projects)。

### 附加文件

你可以上传或附加文档、演示文稿、电子表格、PDF、图片和数据导出文件。适合在以下场景使用附件：

- 总结或比较文件。
- 查找规律或不一致之处。
- 提取、清理或重新组织信息。
- 把文件作为新交付物的来源材料。

ChatGPT 创建文件后，打开预览并检查内容。无需从头开始，就可以继续要求修改。更多信息见[处理文件](/docs/artifacts-viewer)。

### 通过 plugins 连接工具

plugins 可以把 ChatGPT 连接到工作所用的工具和信息，例如 Google Drive、SharePoint、Salesforce 或 Gong。当任务依赖聊天之外的信息、需要在另一个系统中执行操作，或适合复用工作流时，可以使用 plugin。

## 让结果可以直接使用

把第一版结果看成可以检查、质疑和完善的草稿。即使回复很完整，也仍可能遗漏信息或出现错误，因此在使用或分享前应检查重要细节。

**检查工作结果：**

- 核对重要数字、姓名、日期、引文和事实陈述。
- 打开生成文件，检查每个章节、标签页、幻灯片或页面。
- 确认 ChatGPT 使用了正确且最新的来源材料。
- 查找缺失信息和缺少依据的假设。
- 当结果偏离目标时，提出聚焦的修改要求。

然后可以让 ChatGPT 对结果做压力测试：

- “What sources did you use for this?”
- “Cite the source for each major claim.”
- “What assumptions did you make?”
- “What information were you unable to access?”
- “What would change your recommendation?”
- “Check this result against the original files.”

如果 ChatGPT 无法访问某个来源或完成部分任务，让它明确说明。清楚标出的缺口比自信的猜测更容易处理。

<Note>

法律、财务、医疗、安全及其他高风险决策需要适当的专业评审。ChatGPT 应用于辅助知情判断，而不是替代专业人员。

</Note>
