本页列出 Codex 会直接读取的稳定公开环境变量。不列出内部开发变量、测试变量，也不列出你通过 [`env_key`](/docs/config-file/config-advanced#custom-model-providers) 自行选择的提供方专属 secret 名称。

## 核心位置

<div className="doc-table-wrap">

| 变量 | 使用方 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `CODEX_HOME` | CLI、IDE 扩展、app-server、安装器 | `~/.codex` | 设置 Codex 状态根目录，包括配置、认证、日志、会话、技能和 standalone package 元数据。如果设置该变量，目录必须已经存在。 |
| `CODEX_SQLITE_HOME` | CLI 与 app-server 状态 | `CODEX_HOME` | 设置 SQLite-backed 状态的存储位置。`sqlite_home` 配置项优先生效。相对路径会从当前工作目录解析。 |

</div>

关于 `CODEX_HOME` 下保存的文件，参见[配置与状态文件位置](/docs/config-file/config-advanced#config-and-state-locations)。

## 安装器变量

这些变量适用于从 `https://chatgpt.com/codex/install.sh` 和 `https://chatgpt.com/codex/install.ps1` 提供的 standalone 安装脚本。

<div className="doc-table-wrap">

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `CODEX_NON_INTERACTIVE` | `false` | 设为 `1`、`true` 或 `yes` 可跳过安装器提示。提示会使用默认回答，因此它适合脚本化安装和更新，不适合作为首次设置的替代。 |
| `CODEX_INSTALL_DIR` | macOS/Linux 上为 `~/.local/bin`；Windows 上为 `%LOCALAPPDATA%\Programs\OpenAI\Codex\bin` | 改变可见 `codex` 命令的安装位置。standalone package cache 仍位于 `CODEX_HOME/packages/standalone`。 |

</div>

如需无人值守安装，请在运行下载后安装器的 shell 中设置 `CODEX_NON_INTERACTIVE=1`：

<CodeBlock code={"curl -fsSL https://chatgpt.com/codex/install.sh | CODEX_NON_INTERACTIVE=1 sh"} language="bash" />

<CodeBlock code={"$env:CODEX_NON_INTERACTIVE=1; irm https://chatgpt.com/codex/install.ps1 | iex"} language="powershell" />

## 认证与网络

<div className="doc-table-wrap">

| 变量 | 使用方 | 说明 |
| --- | --- | --- |
| `CODEX_API_KEY` | `codex exec` | 为单次非交互运行提供 API key。只支持 `codex exec`；运行仓库可控代码时，请内联设置它，而不是在整个 job 范围内设置。 |
| `CODEX_ACCESS_TOKEN` | CLI、app-server、受信任自动化 | 为受信任自动化提供 ChatGPT 或 Codex 访问令牌。若要持久登录，请把它通过管道传给 `codex login --with-access-token`。 |
| `CODEX_CA_CERTIFICATE` | HTTPS、登录和 WebSocket 客户端 | 指向 PEM CA bundle，用于存在企业 TLS interception 或 private root CA 的环境。优先级高于 `SSL_CERT_FILE`。 |
| `SSL_CERT_FILE` | HTTPS、登录和 WebSocket 客户端 | 当 `CODEX_CA_CERTIFICATE` 未设置时使用的备用 PEM CA bundle 路径。 |

</div>

对于提供方 API keys，请在模型提供方配置中设置 [`env_key`](/docs/config-file/config-advanced#custom-model-providers)。Codex 会读取该配置命名的变量，因此变量名本身并不是固定的 Codex 环境变量。

关于自动化 secret 处理，参见[使用 API key 认证](/docs/non-interactive-mode#use-api-key-auth)。关于 access token 设置，参见[Access tokens](/docs/enterprise/access-tokens)。

## 诊断

<div className="doc-table-wrap">

| 变量 | 使用方 | 说明 |
| --- | --- | --- |
| `RUST_LOG` | CLI 与 app-server | 控制 Rust 日志过滤和详细程度。除非设置更详细的值，否则 `codex exec` 默认输出 `error`。 |

</div>

`RUST_LOG` 接受 `error`、`warn`、`info`、`debug` 和 `trace` 等值，也接受更有针对性的 Rust 日志过滤器，例如 `codex_core=debug,codex_tui=debug`。

交互式 CLI 默认把诊断记录在有界本地存储中，但明文 `codex-tui.log` 文件是 opt-in。需要用于排障的明文日志时，请显式设置 `log_dir`：

<CodeBlock code={"RUST_LOG=debug codex -c log_dir=./.codex-log\ntail -F ./.codex-log/codex-tui.log"} language="bash" />

在非交互模式下，`codex exec` 会内联打印消息，而不是写入单独的 TUI 日志文件。
