配置完成后，本地客户端会通过 AWS 管理的认证与访问控制，把模型请求发送到 Bedrock。

## 工作方式

当你把 Amazon Bedrock 配置为本地 ChatGPT Work 或 Codex 界面的模型提供方时，OpenAI 托管的 Responses API 不在请求路径中。本地客户端会把模型请求发送到 Amazon Bedrock，由 Bedrock 为受支持的 OpenAI 模型提供兼容 OpenAI Responses API 的实现。

<Callout kind="note">

认证采用 AWS 原生方式。用户使用 Bedrock API key 或 AWS IAM 凭据认证；这个提供方不使用 ChatGPT 登录，也不使用 `OPENAI_API_KEY`。

</Callout>

## 开始之前

请确认你已经具备：

-   Amazon Bedrock 中受支持 OpenAI 模型的访问权限。
-   所选模型可用的 AWS Region。
-   已为 AWS 账户配置 Amazon Bedrock Mantle 路径的认证。

## 配置模型提供方

在 `~/.codex/config.toml` 中加入 Amazon Bedrock Mantle 路径的 `amazon-bedrock` 模型提供方。ChatGPT 桌面应用、Codex CLI、IDE 扩展和 SDK 读取相同的本地配置层。是否指定模型是可选的；需要时可以显式选择一个受支持模型。

<CodeBlock code={"model_provider = \"amazon-bedrock\""} language="toml" />

<Callout kind="note">

本指南覆盖受支持商业 AWS Region 中的 Amazon Bedrock Mantle 路径。本地 ChatGPT Work 与 Codex 界面不支持 AWS GovCloud Region 中的 Bedrock Mantle 端点。

</Callout>

## 认证选项

本地 ChatGPT Work 与 Codex 界面支持两条 Bedrock 认证路径，并按以下顺序检查：

1.  Bedrock API key。
2.  AWS SDK 凭据链。

### 选项 1：Bedrock API key

在本地客户端会读取的环境中设置 Bedrock API key。使用 API key 认证时，必须指定 Region。

<CodeBlock code={"export AWS_BEARER_TOKEN_BEDROCK=<your-bedrock-api-key>\nexport AWS_REGION=us-east-2"} language="bash" />

### 选项 2：AWS SDK 凭据

如果你的组织通过 AWS SDK 凭据链管理 Bedrock 访问，请使用这条路径。本地客户端可以使用以下标准 AWS SDK 凭据来源：

#### 共享 AWS 配置文件

配置共享的 AWS `config` 和 `credentials` 文件：

<CodeBlock code={"aws configure"} language="bash" />

#### 环境变量

设置标准 AWS SDK 凭据环境变量：

<CodeBlock code={"export AWS_ACCESS_KEY_ID=<your-access-key-id>\nexport AWS_SECRET_ACCESS_KEY=<your-secret-access-key>\nexport AWS_SESSION_TOKEN=<your-session-token>"} language="bash" />

#### AWS Management Console 凭据

使用 AWS Management Console 凭据登录：

<CodeBlock code={"aws login"} language="bash" />

#### AWS SSO 或具名 profile

使用 AWS SSO 登录并选择具名 profile：

<CodeBlock code={"aws sso login --profile codex-bedrock\nexport AWS_PROFILE=codex-bedrock"} language="bash" />

#### 联合身份

对于企业 SSO 或 OIDC 联合身份，请在本地客户端之外使用 `credential_process` 配置联合身份，让 AWS SDK 解析凭据。浏览器登录、token 交换、缓存和刷新应放在 AWS profile 的 `credential_process` helper 中。

## 桌面应用与 IDE 扩展

桌面 App 和 IDE 扩展可能不会继承 shell 中的环境变量。请把必需值写入 `~/.codex/.env`，然后重启 App 或扩展。

<CodeBlock code={"export AWS_BEARER_TOKEN_BEDROCK=<your-bedrock-api-key>\nexport AWS_REGION=us-east-2"} language="bash" />

## 验证配置

-   在 Codex CLI 中打开 `/status`，确认 Codex 正在使用 `amazon-bedrock` 模型提供方。
-   在 ChatGPT 桌面应用中选择 Work 或 Codex，重启应用后再开始新任务。
-   在 IDE 扩展中，重启扩展后再开始新会话。
-   确认所选模型在配置的 AWS Region 中可用，并且 AWS identity 有权访问该 Bedrock 模型。

## 支持的模型

使用精确模型 ID：

<CodeBlock code={"openai.gpt-5.6-sol\nopenai.gpt-5.6-terra\nopenai.gpt-5.6-luna\nopenai.gpt-5.5\nopenai.gpt-5.4"} language="text" />

模型可用性会因 AWS Region 而异。选择模型前，请查看 [AWS Region 对模型的支持情况](https://docs.aws.amazon.com/bedrock/latest/userguide/models-region-compatibility.html)。

## 功能可用性

此配置支持本地 ChatGPT Work 与 Codex 工作流。Web 端托管的 ChatGPT Work、Codex 云端，以及依赖 OpenAI 托管云服务、托管工具或云端管理发现能力的功能当前不可用。

<Callout kind="note">

Fast Mode 不适用于 Amazon Bedrock。Fast Mode 使用优先级处理，而 Amazon Bedrock 的初始方案仅支持按需推理。

</Callout>

## 故障排查

如果配置失败，请检查以下内容：

-   模型 ID 与受支持模型完全匹配。
-   你指定的是该模型可用的 AWS Region。
-   Bedrock API key 或 AWS 凭据有效且未过期。
-   AWS identity 有权访问所选 Bedrock 模型。
-   `AWS_BEARER_TOKEN_BEDROCK` 没有被设为已过期或非预期的 key。
-   对于桌面应用或 IDE 扩展用法，必需的环境变量已经存在于 `~/.codex/.env`。

OpenAI Support 可以帮助处理 ChatGPT Work 与 Codex 客户端设置、配置、本地 CLI 行为、桌面应用行为、IDE 扩展行为，以及本地产品体验。

对于 AWS 凭据、IAM 权限、Bedrock 模型访问、配额、计费、区域可用性、Bedrock 请求失败、AWS 服务日志或 Bedrock 服务行为，请联系客户的 AWS 管理员或 AWS Support。
