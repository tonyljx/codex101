电商非常适合 Skill，因为大量工作都有同一个特点：**输入每天在变，但分析方法、业务规则和输出模板高度重复。**

不过，电商领域公开的“评论分析”“Listing 优化”“广告复盘”Skill 质量参差不齐。更可靠的做法是：用厂商 Skill 负责 Shopify、抓取、表格和支付等通用能力，再把品牌、渠道、指标和合规规则写成自己的业务 Skill。

![真实电商数据进入评论分析、Listing 优化和广告复盘，并由人工确认动作](/images/docs/skills/ecommerce-illustration.webp)

<span id="best-use-cases"></span>

## 最适合 Skill 的电商工作

优先考虑下面几类：

- Shopify 主题、应用、Admin API 与 Storefront 开发；
- 商品评论、客服工单和退货原因分析；
- 竞品 Listing、价格、活动和页面变化监控；
- 商品标题、卖点和多语言内容生成；
- 广告周报、异常下钻和素材复盘；
- CSV / Excel 清洗、合并、指标计算和报表；
- Checkout、订阅、Marketplace 与支付上线检查。

它们通常都满足四个条件：重复发生、有稳定输入、可以定义输出格式、结果能被人工或数据验证。

<span id="quick-pick"></span>

## 先看结论

| 你的任务 | 优先选择 | 来源类型 | 说明 |
| --- | --- | --- | --- |
| 开发 Shopify 商店、主题或应用 | Shopify AI Toolkit / Liquid Skills | [Shopify 官方](https://github.com/Shopify/Shopify-AI-Toolkit) | 处理平台 API、Liquid、应用和开发规范 |
| 搜索竞品与抓取单页 | Firecrawl Search / Scrape | [Firecrawl 官方](https://github.com/firecrawl/cli/tree/main/skills) | 获取公开网页并转成结构化、可分析内容 |
| 追踪价格、活动或 Listing 变化 | Firecrawl Monitor | [Firecrawl Monitor Skill](https://github.com/firecrawl/cli/blob/main/skills/firecrawl-monitor/SKILL.md) | 适合持续变化检测，不只是一次性调研 |
| 清洗平台导出的 CSV / Excel | `xlsx` | [Anthropic Skills](https://github.com/anthropics/skills/tree/main/skills/xlsx) | 保留公式、格式、图表并检查计算错误 |
| 实现 Checkout、订阅或 Connect | `stripe-best-practices` | [Stripe 官方](https://github.com/stripe/ai/tree/main/skills/stripe-best-practices) | 约束支付状态、Webhook、幂等和安全边界 |
| 评论、Listing、广告和客服分析 | 自定义业务 Skill | 团队自建 | 需要品牌、渠道、KPI、分类体系和合规规则 |

最重要的判断是：**公开 Skill 是否真的包含你的平台规则和数据连接。** 没有真实数据源的“竞品分析 Skill”只能给框架，不能自动知道当前价格、库存或广告表现。

## 推荐 Skill 组合

### 1. Shopify AI Toolkit

**推荐指数：★★★★★（Shopify 技术团队）**

Shopify 官方公开了面向 AI 开发工具的 Skill 集合，覆盖 Admin、应用审核、Liquid、主题和相关开发工作流。它最适合解决“怎么正确开发 Shopify”，而不是代替运营人员做选品或广告决策。

适合：

- Liquid 主题和可访问性检查；
- Shopify App、Admin API 和 GraphQL；
- Storefront / Hydrogen 开发；
- 应用审核前的规则检查；
- 维护平台版本与开发约定。

使用前应明确商店环境、API 版本、所需 scopes 和测试账户。不要让 Agent 在未确认权限与目标商店时直接修改生产商品或订单。

参考：[Shopify AI Toolkit](https://github.com/Shopify/Shopify-AI-Toolkit)。

### 2. Firecrawl Search / Scrape / Monitor

**推荐指数：★★★★★（竞品与公开网页研究）**

Firecrawl 的价值不是“自动写一份竞品报告”，而是为报告提供可追踪的公开网页证据。

按任务选择：

| 需求 | 应用方式 |
| --- | --- |
| 还不知道有哪些竞品 | Search：先发现品牌、商品页和一手来源 |
| 已知一个商品页 | Scrape：提取标题、价格、卖点、规格和页面文本 |
| 需要整个分类或站点结构 | Map / Crawl：发现并批量处理受控范围内的 URL |
| 需要知道何时发生变化 | Monitor：监控价格、活动、库存文案或政策页变化 |

一个好的竞品 Skill 应要求保留：来源 URL、抓取时间、市场 / 币种、商品变体和证据原文。否则不同地区价格、会员价和过期活动很容易被混在一起。

参考：[Firecrawl CLI Skills](https://github.com/firecrawl/cli/tree/main/skills)。

### 3. XLSX / Spreadsheet Skill

**推荐指数：★★★★★**

广告、订单、退货、库存和评论数据最终经常还是 CSV / Excel。Anthropic 官方 `xlsx` Skill 可用于创建、读取、编辑和验证工作簿，适合作为所有分析流程的“数据准备层”。

建议固定：

- 原始数据表只做最小清洗，并保留导出时间；
- 指标使用公式或可复算步骤，不手填汇总值；
- 平台、市场、SKU、币种和时区统一；
- 检查 `#REF!`、`#DIV/0!`、缺失行和重复订单；
- 报告结论能回到具体数据行或透视表。

它可以计算 ROAS，但不会自动知道你公司的利润口径、归因窗口或退款处理方式，这些要写进自己的广告分析 Skill。

### 4. Stripe Best Practices

**推荐指数：★★★★☆**

如果你开发独立站、订阅电商或 Marketplace，Stripe 官方 Skill 比通用支付 Prompt 更可靠。Stripe 仓库还包含 Connect 推荐、文档检索和升级相关 Skill，可按实际支付形态选择。

必须验证：

- 商品价格由服务端或 Stripe Price 决定；
- 下单与发货权益来自服务端确认的支付状态；
- Webhook 验签且重复投递不会重复创建订单；
- 库存扣减、退款、取消和支付失败有明确状态机；
- Connect 平台的商家归属、手续费和 KYC 路径清楚。

参考：[Stripe Agent Skills](https://github.com/stripe/ai/tree/main/skills)。

### 5. Review Analyzer（建议自建）

**推荐指数：★★★★★**

评论分析的核心不是情绪摘要，而是把用户声音变成可追踪的产品和运营输入。

建议固定流程：

```text
校验来源、时间与商品变体
→ 去重并标记低信息评论
→ 按产品 / 物流 / 包装 / 客服分类
→ 统计问题频率与严重度
→ 保留代表性证据和 URL / 行号
→ 区分事实、用户主观感受与分析假设
→ 输出产品、内容和服务的改进优先级
```

验收时应抽样回看原评论，确认分类准确；不要只看模型生成的百分比。

### 6. Listing Optimizer（建议自建）

**推荐指数：★★★★☆**

不要只写“优化一下 Listing”。Skill 应保存：

- 平台字段和字符限制；
- 品牌语气、目标人群和核心卖点；
- 已验证关键词及其来源；
- 禁用词、合规声明和不能证明的功效；
- 标题、Bullet、描述和后台字段的职责；
- 不同市场的语言、单位、尺寸和文化规则。

输出最好附上“原文 → 修改 → 修改理由 → 证据来源”，方便运营审核，而不是直接覆盖线上内容。

### 7. Ad Performance Review（建议自建）

**推荐指数：★★★★★**

广告复盘 Skill 必须先读真实导出数据，再给解释。

```text
核对时间、币种、归因窗口与数据完整性
→ 计算花费 / 展现 / 点击 / CTR / CVR / CPA / ROAS
→ 找同比或环比异常
→ 下钻 Campaign / Ad Group / Creative / SKU
→ 区分流量问题、转化问题和客单价问题
→ 把数据事实与原因假设分开
→ 给出有上限、可回滚的预算或素材实验
```

建议让 Skill 输出“证据”“假设”“建议动作”“验证指标”四列，防止把相关性写成因果关系。

## 三个高频工作流

### 工作流 A：新品上架

```text
Firecrawl Search 发现竞品与一手商品页
→ Scrape 提取价格、规格、卖点和页面结构
→ Review Analyzer 总结用户问题
→ 人工确认定位、差异化和可证明卖点
→ Listing Skill 生成各平台字段
→ 合规与本地化检查
→ Shopify Skill 完成技术上架或主题实现
→ 上线页面 QA
```

最终交付不应只有文案，还应包含来源清单、抓取日期、关键词依据和待人工确认项。

### 工作流 B：每周广告复盘

```text
导出平台原始数据
→ XLSX Skill 清洗并统一口径
→ Ad Review Skill 找异常并下钻
→ Creative Skill 汇总素材表现
→ 生成事实 / 假设 / 动作 / 验证指标
→ 人工确认预算变化
→ 下周用相同口径复盘
```

不要让 Agent 在没有预算上限、账户范围和人工确认的情况下直接改生产广告账户。

### 工作流 C：竞品持续监控

```text
维护竞品、市场和 URL 清单
→ Firecrawl Monitor 追踪价格 / 活动 / 页面变化
→ 过滤导航、时间戳等无意义变化
→ Competitor Skill 判断变化类型和影响
→ 生成带前后证据的周报
→ 将已确认变化写回竞品档案
```

监控比反复从零搜索更适合长期运营，但要定期检查 URL 是否跳转、地区是否变化、页面是否要求登录。

## 数据与合规边界

电商 Skill 经常接触客户、订单、平台数据和公开网页，至少要守住这些边界：

1. 只抓取有权访问的公开内容，不绕过登录、验证码或访问控制；
2. 遵守平台条款、robots 规则、频率限制和适用法律；
3. 上传评论或客服数据前，移除姓名、电话、地址、订单号等个人信息；
4. 广告、销量和利润结论注明时间范围、币种、市场与归因口径；
5. 价格和库存是时效数据，输出必须带抓取时间；
6. 产品功效、折扣和竞品比较必须有证据，不能让模型补全不存在的声明；
7. 任何发布、改价、调预算和退款动作都应有明确账户范围与人工确认。

<span id="custom-skills"></span>

## 最值得自己做的 Skill

| 自定义 Skill | 建议沉淀内容 | 最小验收标准 |
| --- | --- | --- |
| `review-analyzer` | 分类体系、频率、严重度、证据与优先级 | 抽样评论可回溯，分类统计可复算 |
| `listing-writer` | 品牌语气、关键词、字段限制、禁用词 | 每个卖点有证据，不超平台限制 |
| `ad-weekly-review` | KPI、归因口径、异常阈值、下钻顺序 | 事实与假设分开，建议有验证指标 |
| `competitor-monitor` | 竞品、市场、URL、变化类型与通知阈值 | 周报带前后差异、来源和时间 |
| `customer-voice` | 工单、评论、退货原因的统一分类 | 不含 PII，同类问题可跨渠道聚合 |
| `localization-review` | 语言、单位、文化、合规和品牌词汇表 | 由目标市场人员抽样确认 |
| `shopify-release` | 主题预览、应用权限、回滚与线上冒烟 | 不直接改生产，发布后核心流程通过 |

一个实用原则：

> 不要做“万能电商运营 Skill”，而要把数据获取、表格处理、评论、Listing、广告和发布拆成边界明确的 Skill。
