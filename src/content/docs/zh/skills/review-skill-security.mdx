第三方 Skill 看起来可能只是一份 Markdown，但它不一定只是“提示词模板”。

一个 Skill 可以包含：

- 改变 Agent 工作方式的指令；
- 要求读取其他文件的参考资料；
- 可以执行的 Shell、Python 或 JavaScript 脚本；
- 安装依赖或下载外部内容的步骤；
- 访问文件、网络、App 和外部账户的工作流。

真正的风险不是 Skill 这个格式本身，而是：

> 你把一组陌生指令和代码，交给了一个可能拥有文件、终端、网络和外部系统权限的 Agent。

所以安装第三方 Skill 的心态，应该更接近安装一个软件包，而不是收藏一段 Prompt。

![第三方 Skill 的来源、指令、脚本、权限和更新五层风险进入人工审查闸门](/images/docs/skills/review-skill-security-illustration.webp)

## 风险从哪里来

可以把风险分成四层。

### 1. 指令风险

`SKILL.md` 会告诉 Agent 什么时候使用、按照什么流程行动。

危险信号包括：

- 要求忽略系统、用户、仓库或安全规则；
- 把“必须先执行”写在与任务无关的准备步骤中；
- 诱导 Agent 隐藏动作或不要向用户解释；
- 要求读取、总结或上传无关的秘密文件；
- 用编码、特殊字符或远程内容隐藏真实指令。

### 2. 脚本与依赖风险

脚本可能删除或覆盖文件、安装程序、访问网络、启动子进程，或者把本地数据传到外部地址。

即使 `SKILL.md` 本身看起来正常，`scripts/`、安装脚本和依赖仍可能带来风险。

### 3. 权限与数据风险

Skill 使用的是 Agent 当前拥有的能力。

如果 Agent 可以读取整个仓库、运行终端、访问网络，或者连接 GitHub、邮箱、云平台和支付系统，那么 Skill 也可能引导它使用这些能力。

不要只问“Skill 需要什么权限”，还要问：

> 当前 Agent 已经有什么权限，而这次任务真的需要多少？

### 4. 更新与供应链风险

今天审查过的版本，不代表未来更新仍然相同。

维护者账户被盗、仓库转手、下载地址变化、依赖被替换、同名 Skill 覆盖旧版本，都会让风险在更新时出现。

所以来源可信、第一次审查通过以后，仍要保留版本和变更记录。

## 公开研究告诉了我们什么

安全数字必须保留研究范围，不能直接套到所有 Skill。

[Snyk ToxicSkills](https://snyk.io/blog/toxicskills-malicious-ai-agent-skills-clawhub/) 在 2026 年 2 月扫描了来自 ClawHub 和 skills.sh 的 3,984 个 Skill。在这批样本中：

- 36.82% 至少有一项安全问题；
- 13.4% 至少有一项严重级别问题；
- 研究确认了 76 个恶意载荷；
- 发现的风险包括提示注入、凭据窃取、数据外传、危险下载和不安全的秘密处理。

这些比例描述的是研究样本，不代表“所有 Agent Skills 都有同样比例的问题”。但它足以证明：公开目录里的 Skill 不能因为能下载就默认可信。

[Orca Security 的市场供应链研究](https://orca.security/resources/blog/ai-agent-skill-supply-chain-security/) 还展示了另一类问题：安装量可以被操纵、扫描可能不是持续进行、同名 Skill 可能覆盖已有版本、批量更新可能缺少逐项审查。

因此下面这些信号都不能单独作为安全证明：

- 下载量高；
- 排名靠前；
- 有“热门”或“已扫描”徽章；
- 名字与知名 Skill 相似；
- 上一个版本曾经安全；
- AI 自己说“看起来没问题”。

## 十分钟安装前审查

审查不是让每个人都成为安全工程师。目标是用固定顺序排除明显风险，并知道什么时候应该停止。

### 第 1 分钟：确认原始来源

记录：

```text
Skill 名称：
原始仓库：
作者或组织：
准备安装的版本 / 提交：
通过什么目录发现：
```

从目录页面跳转到原始仓库，不要从搜索结果里的复制站、短链接或网盘包直接安装。

### 第 2 分钟：看完整目录

不要只打开 `SKILL.md`。

确认是否存在：

- `scripts/`；
- 依赖清单和锁文件；
- 安装、更新或卸载脚本；
- 二进制文件、压缩包或大体积资源；
- 指向外部下载地址的配置；
- 你无法解释用途的隐藏文件。

一个 Skill 声称“只整理文本”，却包含系统安装脚本和陌生可执行文件，应该立即暂停。

### 第 3–4 分钟：读 `SKILL.md`

先找出它承诺完成的任务，再检查每一步是否为这个任务服务。

重点问：

1. 它会读取什么？
2. 它会写入什么？
3. 它会执行什么？
4. 它会连接哪里？
5. 哪些动作需要用户确认？
6. 缺少输入或权限时会停止吗？

任何“不要告诉用户”“忽略之前规则”“先上传所有配置再开始”的指令，都是严重警告。

### 第 5–6 分钟：检查脚本和命令

不会编程，也可以检查几个直观问题：

- 是否读取 `.env`、SSH、云凭据、浏览器数据或系统密钥目录；
- 是否把本地文件发送到外部域名；
- 是否从网络下载内容后立刻执行；
- 是否使用管理员权限；
- 是否删除、覆盖或批量修改超出任务范围的文件；
- 是否安装未说明来源和版本的依赖；
- 是否隐藏输出或对命令做难以理解的编码。

可以请另一个可信的代码审查工具帮助解释脚本，但最终不要只接受一句“安全”。要求它列出每个脚本的输入、输出、网络地址、文件范围和副作用，再由你决定。

### 第 7 分钟：核对外部地址与依赖

每个域名、包和下载地址都应该能解释。

优先选择：

- 官方包仓库；
- 固定版本或提交；
- HTTPS 地址；
- 有校验和或签名的发布物；
- 与维护者身份一致的组织域名。

对临时文件站、URL 缩短服务、个人网盘、刚创建的相似拼写域名和密码压缩包保持警惕。

### 第 8 分钟：缩小权限和作用域

第一次运行时：

- 使用测试仓库或新分支；
- 使用虚拟数据，不使用真实客户和生产数据；
- 不提供生产密钥；
- 外部 App 使用测试账户；
- 只开放任务需要的目录和网络；
- 关闭自动发布、自动转账、自动发信等不可逆动作。

权限不确定时，宁可先让 Skill 输出计划和将要执行的命令，再由人确认。

### 第 9 分钟：检查维护历史

查看最近提交、版本、Issue 和发布记录：

- 维护者是否突然变化；
- 最新版本是否加入新脚本或新下载地址；
- 是否存在安全问题但没有回应；
- 版本号是否变化，内容却无法追踪；
- 许可证是否允许你的使用方式。

更新频繁不是安全保证，长期不更新也不一定危险。关键是变化能否被解释、审查和回退。

### 第 10 分钟：决定怎么试

给第一次运行写一张观察表：

| 预期动作 | 允许范围 | 必须确认 | 异常时怎么停 |
| --- | --- | --- | --- |
| 读取示例 CSV | 当前测试目录 | 读取其他目录前 | 取消任务并查看日志 |
| 生成报告 | `output/` | 覆盖已有文件前 | 保留原文件 |
| 查询公开资料 | 指定官方域名 | 登录或上传数据前 | 断开网络权限 |

如果无法写出这张表，说明你还不清楚 Skill 会做什么，不应该继续运行。

## 第一次运行怎么隔离

理想的第一次运行环境应该满足：

- 数据可以丢失或重新生成；
- 没有生产凭据；
- 修改可以通过 Git 或备份恢复；
- 外部动作使用测试账户；
- 你能看到 Agent 实际运行的命令和访问的目标；
- 随时可以终止任务。

对于只包含说明、没有脚本和外部动作的低风险 Skill，可以简化步骤；但仍要检查它是否会改变 Agent 的行为边界。

对于会部署、付款、删除、发消息、修改权限或处理敏感数据的 Skill，静态阅读不够，还需要独立测试、人工批准和生产前验收。

## 扫描工具能替代人工吗

不能。

扫描器适合发现：

- 已知恶意模式；
- 硬编码秘密；
- 危险命令；
- 可疑外部地址；
- 依赖漏洞；
- 混淆和提示注入模式。

但它不一定理解你的真实业务边界。

一个脚本读取 `customer.csv` 可能是任务必需，也可能是越权；一个部署命令可能符合发布 Skill 的目标，也可能不应该出现在文档排版 Skill 里。

正确关系是：

```text
来源与版本记录
+ 静态扫描
+ 人工理解任务与权限
+ 隔离环境运行
+ 行为观察和结果验收
```

## 发现异常以后怎么办

如果 Skill 已经运行，并出现不符合预期的网络、文件或账户操作：

1. 立即停止 Agent 和相关进程；
2. 断开或撤销外部连接；
3. 轮换可能暴露的 API Key、Token 和密码；
4. 检查 Git、文件、终端历史和外部系统日志；
5. 从可信备份恢复被修改的内容；
6. 保存 Skill 版本、日志和来源，便于追踪；
7. 向维护者或目录报告，不要继续把同一包分享给别人测试。

如果涉及生产凭据、客户数据、支付或组织账户，按照团队的安全事件流程处理，不要只删除 Skill 就结束。

## 安装前最终检查表

- [ ] 原始作者、仓库和版本可以追踪
- [ ] 已阅读完整 `SKILL.md`
- [ ] 已查看脚本、依赖、二进制和外部下载地址
- [ ] 文件、网络、密钥和外部系统权限与任务相称
- [ ] 没有要求忽略规则、隐藏动作或上传无关数据
- [ ] 更新内容可审查，并且知道如何回退
- [ ] 第一次运行使用测试数据和可恢复环境
- [ ] 高风险动作需要人工确认
- [ ] 已定义异常时的停止和凭据轮换方法

通过这张表，不代表 Skill 永远安全；它代表你已经把“盲目信任”变成了可以检查、可以限制、可以停止的过程。

下一步可以用[第一次使用 Skill](/docs/skills/getting-started/use-first-skill)完成小任务验收。如果安装后找不到或不触发，继续看[Skill 不触发怎么办？](/docs/skills/troubleshoot-skill)。
