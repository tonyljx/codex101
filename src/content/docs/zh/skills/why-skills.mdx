上一篇我们把 Skill 理解成了**给 AI 的 SOP**。

但这时很容易产生一个疑问：

> “我已经有很多好用的 Prompt 了。把 Prompt 存在 Notion、备忘录或者项目里，需要时复制一下，不就可以了吗？”

可以。

而且很多时候，这恰恰是最简单的做法。

Skill 的价值并不是“Prompt 过时了”，而是当你开始把 AI 真正放进日常工作以后，**单纯保存 Prompt 会逐渐遇到一些结构性问题。**

![从重复解释和结果漂移，升级到经验沉淀与团队复用](/images/docs/skills/why-skills-illustration.webp)

<span id="prompt-is-still-useful"></span>

## Prompt 当然还有用

先明确一个容易被误解的地方：

**Skill 不是 Prompt 的替代品。**

如果今天只想让 ChatGPT：

- 帮你润色一封邮件；
- 想 10 个活动标题；
- 解释一个陌生概念；
- 总结一篇临时看到的文章；
- 给一个页面提几条建议；

直接写 Prompt 往往就是最好的方式。

因为这些任务的共同特点是：**临时、变化大、没有必要沉淀成固定流程。**

Skill 真正开始有价值，是当一件事情从“偶尔问一下 AI”变成“这是我工作的一部分”。

<span id="where-prompts-break-down"></span>

## Prompt 在哪里开始吃力

继续用运营周报的例子。

最开始，你可能只有一句：

```text
根据这些数据帮我写一份本周运营周报。
```

用几次以后，你开始补要求：

```text
不要只总结数据，要找异常。
```

后来又补：

```text
异常要分析可能原因，但不要把猜测写成事实。
```

再后来：

```text
最后一定要给下周动作，而且每个动作要对应前面的发现。
```

最后，你得到了一段 1,000 字的“祖传 Prompt”。

它可能很好用，但新的问题出现了。

### 你必须记得每次都带上它

少复制一段，AI 的工作方式就可能变化。

### Prompt 越来越像工作手册

它不再只是“这次做什么”，里面开始混入步骤、判断标准、模板、例子和注意事项。

### 工作材料和工作方法混在一起

每次都要把长期不变的方法和本次才有的数据一起塞给 AI。

### 经验很难继续扩展

如果后面还要加入品牌规范、优秀报告样例、检查清单，单个 Prompt 会越来越臃肿。

这时，你其实已经不是在写 Prompt 了。

你是在维护一套**工作流程**。

<span id="from-answer-to-workflow"></span>

## 从一次答案到稳定工作流

这是理解 Skill 最关键的一步。

使用 AI 可以分成两个阶段：

### 阶段一：我想得到一个好答案

关注的是：

> “这一轮 Prompt 怎么写，才能让结果更好？”

这就是大家熟悉的 Prompt Engineering。

### 阶段二：我想让这项工作以后都稳定完成

关注的问题会变成：

- 应该先做哪一步？
- 什么情况要继续追问？
- 哪些信息必须检查？
- 输出应该符合什么标准？
- 哪些错误绝对不能犯？
- 什么资料需要随时参考？

这时候关注点已经从一句 Prompt，变成了 **Workflow（工作流）**。

Skill 正好是承载这种工作流的一种方式。

可以把变化理解成：

```text
一次问答
    ↓
反复使用的 Prompt
    ↓
稳定的工作步骤
    ↓
可复用的 Skill
```

真正的升级不是“Prompt 变高级了”，而是：

> **你开始把自己的工作方法交给 AI。**

<span id="four-reasons"></span>

## Skill 真正解决的四个问题

### 1. 减少重复解释

如果一套要求每周都要重新讲，它就应该和本次任务分开。

例如：

**长期不变：**

- 周报分析步骤；
- 异常判断标准；
- 输出结构；
- 写作风格；
- 质量检查规则。

**每周变化：**

- 本周数据；
- 本周活动；
- 特殊事件；
- 你这次特别关注的问题。

Skill 保存前一部分，Prompt 只需要负责后一部分。

### 2. 降低结果漂移

生成式 AI 天生存在一定变化。

Skill 不能保证每次答案一模一样，但它可以让 AI 每次都遵循更一致的**过程和标准**。

例如销售团队做客户研究时，可以统一要求：

1. 先确认公司基本信息；
2. 再找最近的重要动态；
3. 判断可能的业务痛点；
4. 区分事实和推测；
5. 最后生成会前问题清单。

不同客户的信息当然不同，但研究方法可以保持一致。

### 3. 把个人经验变成可复用资产

很多人的“AI 能力”其实藏在自己的聊天记录里。

比如一个资深 PM 很清楚怎样 Review PRD：

- 先看目标；
- 再看用户；
- 检查成功指标；
- 找边界条件；
- 检查异常流程；
- 最后才讨论具体方案。

如果这些规则只存在于他的脑子和 Prompt 里，它仍然是个人经验。

如果把它整理成 Skill，就有机会变成团队可以重复使用的工作方法。

### 4. 让复杂工作继续生长

简单 Prompt 通常只有文字说明。

而 Skill 可以继续加入参考资料、模板、示例，必要时还可以加入脚本和工具。

所以它适合从一个简单 SOP 慢慢长成更完整的工作系统。

你不需要第一天就把它做得很复杂。

最好的方式通常是：

> **先让 AI 把一件真实工作做对，再把成功的方法固化下来。**

<span id="when-not-to-use"></span>

## 什么时候不需要 Skill

不是所有事情都值得做成 Skill。

下面几类任务，通常直接 Prompt 更简单：

**只会发生一次的任务**

例如临时写一封特殊邮件。

**高度开放、每次方法都不同的任务**

例如漫无目的的头脑风暴。

**你自己还不知道正确流程的任务**

如果连你都还在探索“到底应该怎么做”，先和 AI 多做几次，不急着固化。

**只是想保存一小段固定文字**

如果只是一个两三句话的常用 Prompt，没有复杂步骤，收藏 Prompt 可能已经足够。

Skill 的目标不是让所有 Prompt 都消失。

它应该只承接那些**值得沉淀的工作方法**。

![判断 Prompt 何时应该升级为 Skill 的纵向漫画](/images/docs/skills/why-skills-comic.webp)

<span id="decision-checklist"></span>

## 一分钟判断要不要做 Skill

拿你现在的一项工作，依次回答下面五个问题：

- 我一个月会做两次以上吗？
- 每次虽然输入不同，但步骤大致一样吗？
- 我是否经常重复告诉 AI 同样的要求？
- 如果漏掉一个步骤，结果质量会明显下降吗？
- 我希望同事也能按照同样的方法完成吗？

如果其中有 **3 个以上回答“是”**，它就非常值得尝试做成 Skill。

比如：

| 工作 | 是否适合 Skill | 原因 |
| --- | --- | --- |
| 每周运营周报 | 很适合 | 高频、步骤固定、输出标准明确 |
| 每个客户的销售会前研究 | 很适合 | 输入变化，但研究框架稳定 |
| 每月商品差评分析 | 很适合 | 分类和分析方法可以复用 |
| 临时给老板写生日祝福 | 不太需要 | 一次性任务 |
| 随便聊一个创业想法 | 不太需要 | 高度开放，没有固定流程 |

到这里，你应该已经能回答“为什么需要 Skill”。
