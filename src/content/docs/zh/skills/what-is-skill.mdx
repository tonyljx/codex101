很多人第一次听到 **Skill（技能）**，会以为这是一个偏开发者的功能：是不是要写代码？是不是要学 YAML？是不是只有用 Codex 的程序员才需要？

其实都不是。

如果你是产品经理、运营、销售、电商从业者，甚至只是经常用 ChatGPT 做重复工作的人，Skill 最值得理解的地方只有一句话：

> **Skill 是把你反复教 AI 的“做事方法”，保存成一套可以重复使用的工作流。**

<span id="start-with-a-problem"></span>

## 先从一个真实问题开始

假设你每周五都要让 ChatGPT 帮你写运营周报。

你可能每周都会重复说一遍：

```text
这是本周的数据，请先看流量和转化有没有异常，
再总结本周发生了什么，
然后分析原因，
最后按“核心结论 / 异常 / 原因 / 下周动作”的格式输出。
不要只复述数据，要告诉我哪些变化值得关注。
```

第一次这样做没有问题。

但如果你连续做了 10 周，就会发现几个麻烦：

- 每次都要重新复制同一段要求；
- 忘记补一句要求，结果格式就变了；
- 同样的数据，有时分析得深，有时只是简单总结；
- 同事想复用你的方法，只能向你要那段 Prompt；
- 你的“工作经验”一直藏在聊天记录里，没有真正沉淀下来。

这就是 Skill 想解决的问题。

<span id="what-is-a-skill"></span>

## Skill 到底是什么

OpenAI 把 Skill 定义为一种**可复用、可共享的工作流**：你先告诉 ChatGPT 某类任务应该怎样完成，之后再遇到类似任务时，ChatGPT 可以按照这套方法更稳定地执行。

对非技术用户，更容易理解的比喻是：

> **Prompt 像一次性的任务交代，Skill 更像一份给 AI 的 SOP。**

比如一家电商公司的“差评分析 Skill”，可能规定：

1. 先把评论按产品质量、物流、价格、客服、使用体验分类；
2. 统计每类问题出现的频率；
3. 区分偶发问题和系统性问题；
4. 摘出最有代表性的用户原话；
5. 给出可以执行的产品和运营建议；
6. 最后按固定模板输出。

以后你只需要把一批新评论交给 AI，不必每次从头解释这六步。

这就是 Skill 的核心价值：**把一次“教 AI 做事”，变成以后都可以复用的工作方式。**

<span id="prompt-vs-skill"></span>

## Prompt 和 Skill 的区别

Skill 并不是来取代 Prompt 的。

两者更像是不同层级：

| | Prompt | Skill |
| --- | --- | --- |
| 解决什么 | 这一次要 AI 做什么 | 这类工作以后应该怎么做 |
| 使用频率 | 临时、一次性 | 重复、长期 |
| 内容重点 | 当前任务和要求 | 稳定的方法、步骤和标准 |
| 是否适合共享 | 可以，但容易散落 | 更适合沉淀和团队复用 |
| 结果一致性 | 依赖你每次写得是否完整 | 更容易保持固定流程 |

可以把它记成一句话：

> **Prompt 是告诉 AI“这次怎么做”，Skill 是教会 AI“以后遇到这类事情怎么做”。**

例如：

```text
Prompt：
“帮我分析下面这 200 条 Amazon 评论。”

Skill：
“以后分析商品评论时，都按照问题分类 → 频率统计 →
代表性评论 → 根因判断 → 优先级 → 改进建议的流程完成。”
```

真正工作时，两者往往会一起使用。

Skill 提供“方法”，Prompt 提供“这一次具体要处理的任务和材料”。

<span id="what-can-a-skill-contain"></span>

## Skill 里可以放什么

一个 Skill 并不只是“一大段 Prompt”。

它可以包含几类东西：

**1. 工作说明**

告诉 AI 这项工作应该如何完成，例如先分析什么、后判断什么、最后输出什么。

**2. 示例**

告诉 AI 什么叫好结果，什么叫差结果。

**3. 参考资料**

比如品牌规范、写作风格、产品资料、分析框架、字段说明、报告模板。

**4. 固定流程**

如果任务比较结构化，可以明确要求 AI 每次都按同样的步骤执行。

**5. 必要时的代码或工具**

某些更复杂的 Skill 还可以附带脚本或工具，让步骤更加确定。

但如果你是第一次做 Skill，不需要从代码开始。

对于大多数 PM、运营、销售和电商工作，**先把“工作步骤写清楚”就已经很有价值。**

<span id="when-to-think-about-skills"></span>

## 什么时候该想到 Skill

判断一件工作要不要做成 Skill，可以先问自己三个问题：

### 这件事会重复发生吗？

如果你只做一次，普通 Prompt 通常已经足够。

如果你每周、每月、每个客户、每个商品都要做一次，就值得继续判断。

### 这件事有没有相对固定的方法？

比如：

- PRD Review；
- 竞品分析；
- 销售会前准备；
- 会议纪要整理；
- 周报生成；
- 商品评论分析；
- Listing 优化；
- 内容改写；
- 用户反馈归类。

这些任务虽然每次输入不同，但“怎么做”往往很相似。

### 你是否在意结果的一致性？

如果你发现：

> “为什么昨天它记得分析风险，今天又忘了？”

或者：

> “为什么同一个团队的人用 AI，最后出来的报告完全不是一种标准？”

Skill 就开始有价值了。

所以，一个非常实用的判断公式是：

> **重复发生 + 有固定步骤 + 希望结果稳定 = 很适合做成 Skill。**

你甚至可以现在就翻一翻最近一周的 ChatGPT 记录：

**有没有哪一段 Prompt，你复制、修改或重新解释过两次以上？**

如果有，它很可能就是你的第一个 Skill 候选。

> “我把常用 Prompt 收藏起来，不也能重复用吗？为什么还要做 Skill？”

这正是下一篇要解决的问题。

接下来阅读 **《为什么需要 Skill？Prompt 不够用了吗？》**，你会进一步理解 Skill 真正解决的不是“少复制一段文字”，而是如何把 AI 从一次性的聊天工具，变成可以稳定复用工作方法的工具。
