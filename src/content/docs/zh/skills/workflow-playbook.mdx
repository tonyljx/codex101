很多人第一次创建 Skill，会从“我该怎么写 `SKILL.md`”开始。

这通常不是最好的起点。

更有效的方法是先问：

> **我现在有哪些工作，已经在反复让 AI 做？**

Skill 不是为了展示复杂配置，而是为了把一件已经存在的工作，变成 AI 可以稳定重复的流程。

![研究、分析、写作、生成、审核和监控六类常见 Skill 工作流](/images/docs/skills/workflow-playbook-illustration.webp)

<span id="start-from-work"></span>

## 不要从 SKILL.md 开始

假设你是运营，每周都要做一次活动复盘。

与其先想 Skill 的文件结构，不如先把一次真实复盘跑通：

1. 给 AI 活动目标和结果数据；
2. 让它找出目标完成情况；
3. 找出明显异常；
4. 区分事实和推测；
5. 总结做对和做错的地方；
6. 输出下一轮动作。

你和 AI 调整两三轮后，如果这套流程已经比较稳定，再把它整理成 Skill。

这也是更自然的路径：

```text
真实工作
  ↓
和 AI 一起把它做对
  ↓
总结成功步骤
  ↓
定义输入与输出
  ↓
做成 Skill
  ↓
用真实任务继续测试
```

<span id="six-workflows"></span>

## 6 类最常见工作流

绝大多数办公和知识工作 Skill，都可以先从下面六类里找原型。

### 1. 研究型：先收集，再判断

适合：竞品研究、客户研究、行业研究、公司研究、选题调研。

典型流程：

```text
明确研究问题
→ 收集来源
→ 提取事实
→ 对比差异
→ 区分事实 / 推断
→ 形成结论
→ 给出下一步
```

这类 Skill 最重要的不是“写得像专家”，而是**来源、证据和判断边界**。

### 2. 分析型：先检查，再下钻

适合：运营周报、广告数据、用户反馈、商品评论、财务数据。

典型流程：

```text
检查数据完整性
→ 找核心指标变化
→ 找异常
→ 下钻维度
→ 提出可能原因
→ 标记假设
→ 给行动建议
```

好的分析 Skill 应该要求 AI 不只复述数字，而是告诉你：**什么变化值得注意，以及为什么值得继续查。**

### 3. 写作型：先理解，再成稿

适合：文章、公众号、PRD、邮件、方案、社媒内容。

典型流程：

```text
确认受众和目标
→ 提取核心观点
→ 搭结构
→ 写初稿
→ 检查逻辑
→ 调整语气
→ 做读者测试
```

写作 Skill 的价值通常不在“文笔模板”，而在于把你的编辑方法保存下来。

### 4. 生成型：从输入生产标准化交付物

适合：PPT、Excel、报告、Landing Page、商品 Listing、销售 Brief。

典型流程：

```text
检查输入
→ 选择模板
→ 生成结构
→ 填充内容
→ 格式化
→ QA
→ 输出文件 / 页面
```

这类工作尤其适合 Skill，因为交付物通常有明确格式和质量标准。

### 5. 审核型：按清单发现问题

适合：PRD Review、代码 Review、广告素材检查、合同信息核对、网页 QA。

典型流程：

```text
识别对象
→ 按检查清单逐项审核
→ 标记严重程度
→ 给证据
→ 给修复建议
→ 再检查
```

审核 Skill 的核心是**检查项和优先级**，而不是让模型自由发挥。

### 6. 监控型：定期检查变化

适合：竞品动态、价格、SEO 排名、舆情、公司公告、项目状态。

典型流程：

```text
定义监控对象
→ 获取最新状态
→ 与上次比较
→ 判断是否有重要变化
→ 过滤噪声
→ 只报告值得行动的变化
```

如果再结合定时任务、App 或 MCP，这类 Skill 可以进一步变成持续工作的 Agent 流程。

<span id="workflow-template"></span>

## 一个通用拆解模板

不管你做什么行业，都可以用下面 7 个问题设计 Skill。

| 问题 | 你需要想清楚什么 |
| --- | --- |
| 什么时候触发？ | 用户说什么、出现什么材料时应该使用 |
| 输入是什么？ | 文件、数据、URL、聊天内容还是自然语言 |
| 第一步是什么？ | AI 不应该直接跳到最终答案 |
| 中间怎么判断？ | 哪些情况需要下钻、追问或停止 |
| 输出是什么？ | 报告、表格、代码、邮件还是建议 |
| 什么叫做得好？ | 质量标准、模板、示例、检查清单 |
| 什么不能做？ | 不该猜什么、不该自动执行什么 |

一个非常实用的 Skill 骨架就是：

```text
触发条件
→ 输入检查
→ 工作步骤
→ 判断规则
→ 输出格式
→ 质量检查
→ 边界条件
```

## 怎么让工作流更稳定

### 把“形容词”换成“动作”

差的规则：

```text
请深入、专业、全面地分析。
```

更好的规则：

```text
先列出三个最重要的变化；
每个变化给出对应数据；
无法确认的原因标记为“假设”；
最后按影响程度排序。
```

### 明确输入和输出

不要只写“帮我写文章”。

应该明确：

- 输入可能是什么；
- 要不要追问；
- 输出有哪些部分；
- 最终长度和风格；
- 是否需要引用来源。

### 加一个 QA 步骤

很多 Skill 的质量差距就来自最后一步。

例如：

```text
完成后检查：
1. 是否回答了用户真正的问题；
2. 是否把猜测写成事实；
3. 是否遗漏关键输入；
4. 建议是否能执行；
5. 输出是否符合约定格式。
```

### 用 3 个真实任务测试

不要只用一个“完美示例”。

至少测试：

- 一个正常任务；
- 一个输入不完整的任务；
- 一个容易误触发或不该触发的任务。

这样你才能知道这个 Skill 是真的稳定，还是只是刚好在一个例子里表现不错。

## 把第一个流程做成 Skill

如果你还不知道从哪里开始，可以从最近一周找一件满足下面条件的工作：

> **你已经让 AI 做过至少两次，而且第二次又重新解释了一遍怎么做。**

然后直接告诉 ChatGPT / Codex：

```text
我想把刚才这套工作方法做成一个 Skill。
请先总结这次任务里稳定不变的步骤、输入、输出、检查规则和边界，
再帮我生成 Skill，并给出 3 个测试任务。
```

OpenAI 当前的 Skill 创建流程本身也支持通过聊天创建，并使用 `skill-creator` 来辅助生成、修改和排查 Skill。

如果你希望手动理解底层结构，可以继续看 [构建技能](/docs/build-skills)。

如果你更想直接找到可以用的工作流，回到 [Skills 专区](/docs/skills)，从 **AI 网站开发、文章撰写、电商、股票研究** 四个推荐分类开始。
