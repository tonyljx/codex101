## ChatGPT 网页版命令

ChatGPT 网页版有自己的输入框命令菜单。输入 `/` 可查看当前聊天中可用的操作。它不会提供 ChatGPT 桌面 App 或 CLI 的命令集；本参考中的 Codex 斜杠命令、CLI 子命令和 flags 不适用于 ChatGPT 网页版。

## ChatGPT 桌面 App 命令

通用的[命令](/docs/reference/commands)页面涵盖 App 导航、聊天快捷键、键盘自定义，以及聊天、设置、skills、定时任务、plugins 和 pets 的 deep links。

[斜杠命令](/docs/reference/slash-commands)页面涵盖 App 输入框中可用的命令，包括 `/feedback`、`/goal`、`/init`、`/mcp`、`/plan`、`/review` 和 `/status`。

## Codex CLI 命令参考

### 如何阅读本页

本页汇总了所有已文档化的 Codex CLI 命令和选项。你可以按命令名或说明来查找。每个章节都会标明该功能是稳定还是实验性，并指出哪些组合存在更高风险。

<Callout kind="note">

CLI 的大部分默认值都继承自 `~/.codex/config.toml`。如果你在命令行里传入 `-c key=value` 覆盖项，它们会在本次调用中优先生效。关于优先级规则，参见 [配置基础](/docs/config-file/config-basic#configuration-precedence)。

</Callout>

### 命令细节

<span id="codex-interactive"></span>

#### codex（交互模式）

直接运行 `codex` 而不带子命令时，会启动交互式终端 UI（TUI）。智能体会接受前面列出的全局选项，也支持附加图片。Web 搜索默认使用 `cached` 模式；使用 `--search` 可切换到实时浏览。若要进行低摩擦本地工作，请使用 `--sandbox workspace-write --ask-for-approval on-request`。

如果要把 TUI 连接到远程 app server，可使用 `--remote ws://host:port`、`--remote wss://host:port`、`--remote unix://` 或 `--remote unix://PATH`，并将其指向通过 `codex app-server --listen ...` 启动的服务端。如果服务端要求通过 WebSocket 使用 bearer token 认证，可额外传入 `--remote-auth-token-env <ENV_VAR>`。

#### codex app-server

在本地启动 Codex app-server。这个命令主要用于开发和调试，未来可能会变更。

<div className="doc-table-wrap">

| 选项 | 类型 / 可选值 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `--analytics-default-enabled` | boolean | `false` | 为第一方 app-server 客户端默认启用 analytics，除非用户在配置中选择退出。 |
| `--listen` | `stdio:// \| ws://IP:PORT \| unix:// \| unix://PATH \| off` | `stdio://` | 传输监听 URL。用 `stdio://` 表示 JSONL，`ws://IP:PORT` 表示 TCP WebSocket 端点，`unix://` 表示默认 Unix socket，`unix://PATH` 表示自定义 Unix socket，`off` 表示禁用本地传输。 |
| `--stdio` | boolean | `false` | 使用 stdio 传输。等价于 `--listen stdio://`，并且与 `--listen` 互斥。 |
| `--ws-audience` | string |  | 已签名 bearer token 中预期的 `aud` 声明值。要求同时使用 `--ws-auth signed-bearer-token`。 |
| `--ws-auth` | `capability-token \| signed-bearer-token` |  | 为 app-server 的 WebSocket 客户端指定认证模式。若省略，则不会启用 WebSocket 认证；如果监听地址不是本地地址，启动时会给出警告。 |
| `--ws-issuer` | string |  | 已签名 bearer token 中预期的 `iss` 声明值。要求同时使用 `--ws-auth signed-bearer-token`。 |
| `--ws-max-clock-skew-seconds` | number | `30` | 校验已签名 bearer token 的 `exp` 和 `nbf` 声明时，允许的时钟偏差秒数。要求同时使用 `--ws-auth signed-bearer-token`。 |
| `--ws-shared-secret-file` | absolute path |  | 包含 HMAC 共享密钥的文件路径，用于校验已签名的 JWT bearer token。使用 `--ws-auth signed-bearer-token` 时必填。 |
| `--ws-token-file` | absolute path |  | 包含共享 capability token 的文件路径。使用 `--ws-auth capability-token` 时传入，除非你改用 `--ws-token-sha256`。 |
| `--ws-token-sha256` | hexadecimal SHA-256 digest |  | capability-token 认证所期望的 SHA-256 摘要。当客户端 token 来自其他来源时，可用它代替 `--ws-token-file`。 |

</div>

`codex app-server --listen stdio://` 会继续使用默认的 JSONL-over-stdio 传输方式，`codex app-server --stdio` 是这个传输方式的别名。`--listen ws://IP:PORT` 会为 app-server 客户端启用 WebSocket 传输。服务端接受 `ws://` 作为监听 URL；如果客户端通过 `wss://` 连接，则应在前面配置 TLS 终止或安全代理。使用 `--listen unix://` 可在 Codex 默认 Unix socket 上接受 WebSocket 握手；使用 `--listen unix:///absolute/path.sock` 可指定 socket 路径。如果你要为客户端绑定生成 schema，请额外加上 `--experimental`，这样受门控的字段和方法也会一并包含进去。

添加 `--code-mode-host wss://code-mode.example.com/host`，可让 app-server 连接远程 Code Mode host，而不是启动本地 host。这条出站连接与 `--listen` 相互独立，并由 app-server 进程中的所有 thread 共享。只有连接 localhost 或通过 SSH 转发的 host 时才使用 `ws://`。

#### codex remote-control

运行 `codex remote-control` 会以前台方式启动远程控制。使用 `codex remote-control start` 可启动启用了远程控制的本地 app-server daemon，使用 `codex remote-control stop` 则可将其停止。托管 remote-control 客户端和 SSH 远程工作流会使用这些命令；如果你正在构建本地协议客户端，它们不能替代 `codex app-server --listen`。

daemon 运行后，使用 `codex remote-control pair` 可创建并打印一个短期有效的手动配对码。为任意 remote-control 命令加上 `--json` 可获得机器可读输出。对于 `pair`，JSON 响应包含 `pairingCode`、`manualPairingCode`、`environmentId` 和 `expiresAt`。

#### codex app

从终端启动 ChatGPT 桌面 App（macOS 或 Windows）。在 macOS 上，Codex 可以直接打开指定工作区路径；在 Windows 上，Codex 会打印要打开的路径。

<div className="doc-table-wrap">

| 选项 | 类型 / 可选值 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `--download-url` | url |  | 高级覆盖项，用于替换安装阶段使用的 ChatGPT 桌面 App 安装器 URL。 |
| `PATH` | path | `.` | ChatGPT 桌面 App 的工作区路径。在 macOS 上，Codex 会打开该路径；在 Windows 上，Codex 会打印该路径。 |

</div>

`codex app` 会打开已安装的 ChatGPT 桌面 App；如果尚未安装，则启动安装器。在 macOS 上，Codex 会打开给定工作区路径；在 Windows 上，安装后会打印要打开的路径。

#### codex debug app-server send-message-v2

使用内置 app-server 测试客户端，通过 app-server 的 V2 对话线程 / 会话轮次流程发送一条消息。

<div className="doc-table-wrap">

| 参数 | 类型 / 可选值 | 说明 |
| --- | --- | --- |
| `USER_MESSAGE` | string | 通过内置 V2 测试客户端流程发送给 app-server 的消息文本。 |

</div>

这个调试流程会以 `experimentalApi: true` 初始化，然后启动对话线程、发送会话轮次，并流式输出服务端通知。适合在本地复现和观察 app-server 协议行为。

#### codex debug models

以 JSON 形式打印 Codex 看到的原始 model catalog。

<div className="doc-table-wrap">

| 选项 | 类型 / 可选值 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `--bundled` | boolean | `false` | 跳过刷新，只打印当前 Codex 二进制内置的 model catalog。 |

</div>

当你只想检查当前二进制打包的 catalog，而不从远程 models endpoint 刷新时，请使用 `--bundled`。

#### codex debug prompt-input

以 JSON 形式渲染模型实际可见的提示词输入列表。调试指令发现、session 上下文或提示词构造时，可以使用这个命令。

<div className="doc-table-wrap">

| 参数 / 选项 | 类型 / 可选值 | 说明 |
| --- | --- | --- |
| `--image, -i` | `path[,path...]` | 把一张或多张图片附加到用户提示词。可用逗号分隔多个路径，也可重复传入该选项。 |
| `PROMPT` | string | 可选的用户提示词，会追加到 session 上下文之后。 |

</div>

#### codex apply

把最近一次 Codex 云端任务生成的 diff 应用到本地仓库。你必须已经认证，而且对该任务具有访问权限。

<div className="doc-table-wrap">

| 参数 | 类型 / 可选值 | 说明 |
| --- | --- | --- |
| `TASK_ID` | string | 要应用其 diff 的 Codex 云端任务 ID。 |

</div>

Codex 会打印被打补丁的文件；如果 `git apply` 失败（例如发生冲突），则以非零状态码退出。

#### codex review

以非交互方式运行代码评审。请只选择一个评审目标，也可以把自定义评审指令作为提示词传入。

<div className="doc-table-wrap">

| 参数 / 选项 | 类型 / 可选值 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `--base` | branch |  | 评审相对于指定基础分支的改动。 |
| `--commit` | SHA |  | 评审指定 commit 引入的改动。 |
| `--strict-config` | boolean | `false` | 当 `config.toml` 中包含当前 Codex 版本无法识别的字段时，直接报错。 |
| `--title` | string |  | 设置评审摘要中显示的 commit 标题。需要配合 `--commit` 使用。 |
| `--uncommitted` | boolean | `false` | 评审已暂存、未暂存和未追踪的改动。 |
| `PROMPT` | `string \| -（从 stdin 读取）` |  | 自定义评审指令。使用 `-` 可从 stdin 读取指令。 |

</div>

`--uncommitted`、`--base`、`--commit` 和自定义 `PROMPT` 彼此冲突。`--title` 只能与 `--commit` 一起使用。

<span id="codex-archive-and-codex-unarchive"></span>

#### codex archive 与 codex unarchive

按 session ID 或 session 名称归档或恢复已保存的交互会话。当你想清理 session 选择器、但不删除 transcript 时，可以使用这两个命令。session ID 的优先级高于 session 名称。

<CodeBlock code={"codex archive <SESSION>\ncodex unarchive <SESSION>"} language="bash" />

<div className="doc-table-wrap">

| 参数 / 选项 | 类型 / 可选值 | 说明 |
| --- | --- | --- |
| `--remote` | `ws://host:port \| wss://host:port \| unix:// \| unix://PATH` | 在改变归档状态前，先连接到远程 app-server 端点。 |
| `--remote-auth-token-env` | `ENV_VAR` | 当 `--remote` 要求认证时，从这个环境变量读取 bearer token。 |
| `SESSION` | `session ID \| session name` | 要归档或恢复的已保存 session。session ID 的优先级高于 session 名称。 |

</div>

#### codex delete

永久删除一个已保存的交互会话，可按 session ID 或 session 名称指定。只有当你想移除 transcript，而不是仅把它从活动 session 列表中隐藏时，才使用这个命令。

<CodeBlock code={"codex delete <SESSION>\ncodex delete <SESSION_UUID> --force"} language="bash" />

<div className="doc-table-wrap">

| 选项 | 类型 / 可选值 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `--force` | boolean | `false` | 不再提示确认就删除。session 参数必须是 UUID；按名称删除仍需要交互确认。 |
| `--remote` | `ws://host:port \| wss://host:port \| unix:// \| unix://PATH` |  | 删除 session 前先连接到远程 app-server 端点。 |
| `--remote-auth-token-env` | `ENV_VAR` |  | 当 `--remote` 要求认证时，从这个环境变量读取 bearer token。 |
| `SESSION` | session ID | session name |  | 要删除的已保存 session。session ID 优先于 session 名称。 |

</div>

只应对 session UUID 使用 `--force`。按名称删除仍会要求确认，避免 Codex 在名称重复或含糊时直接删除错误的 session。

| `--profile, -p` | NAME | 把 `$CODEX_HOME/NAME.config.toml` 叠加到基础用户配置之上。 |
| `COMMAND...` | `var-args` | 在原生 Windows sandbox 中执行的命令。可执行文件需放在 `--` 之后。 |

</div>

#### codex update

当已安装版本支持 self-update 时，检查并应用 Codex CLI 更新。Debug build 会打印提示，说明应安装 release build。

### 选项组合与安全建议

-   对于可以保持在工作区内的无人值守本地工作，请使用 `--sandbox workspace-write`；除非已经处在专用 sandbox VM 中，否则避免使用 `--dangerously-bypass-approvals-and-sandbox`。
-   如果需要给 Codex 更多目录的写权限，优先使用 `--add-dir`，而不是直接切到 `--sandbox danger-full-access`。
-   在 CI 中把 `--json` 与 `--output-last-message` 组合使用，可以同时捕获机器可读进度和最终自然语言摘要。

## Codex CLI 斜杠命令

### 用斜杠命令控制当前会话

下面这些工作流可以帮助你在不重启 Codex 的情况下持续调整会话。

<span id="set-the-active-model-with-model"></span>

#### 用 `/model` 设置当前模型

1.  启动 Codex 并打开输入框。
2.  输入 `/model` 并按 Enter。
3.  从弹出菜单中选择 `gpt-5.6-luna`、`gpt-5.6-terra` 等模型。

预期结果：Codex 会在对话记录中确认模型已切换。你也可以运行 `/status` 再确认一次。

<span id="toggle-fast-mode-with-fast"></span>

#### 用 `/fast` 切换快速 service tier

1.  输入 `/fast on`、`/fast off` 或 `/fast status`。
2.  如果你希望这个设置持久生效，可以在 Codex 提示保存更新时确认。

预期结果：Codex 会说明当前模型的 Fast service tier 是否已在当前对话线程开启。在 TUI 底部状态栏中，你也可以用 `/statusline` 显示快速模式的状态项。

Fast tier 命令由模型目录驱动。如果当前模型没有声明 Fast tier，Codex 不会显示 `/fast`。

<span id="set-a-communication-style-with-personality"></span>

#### 用 `/personality` 设置沟通风格

使用 `/personality` 可以在不重写提示词的情况下调整 Codex 的表达方式。

1.  在当前对话中输入 `/personality` 并按 Enter。
2.  从弹出菜单中选择一种风格。

预期结果：Codex 会在对话记录中确认新的风格，并在后续回复中持续采用它。

Codex 支持 `friendly`、`pragmatic` 和 `none` 三种沟通风格（personality）。使用 `none` 可关闭沟通风格指令。

如果当前模型不支持沟通风格专用指令，Codex 会隐藏这个命令。

<span id="switch-to-plan-mode-with-plan"></span>

#### 用 `/plan` 切换到计划模式

1.  输入 `/plan` 并按 Enter，把当前对话切换到计划模式。
2.  你也可以直接附带一段内联提示词，例如 `/plan Propose a migration plan for this service`。
3.  使用内联 `/plan` 参数时，你也可以粘贴内容或附加图片。

预期结果：Codex 会进入计划模式，并把你可选提供的内联提示词作为第一条计划请求。

当某个任务已经在运行时，`/plan` 会暂时不可用。

<span id="set-or-view-a-task-goal-with-goal"></span>

#### 用 `/goal` 设置或查看任务目标

1.  输入 `/goal <objective>` 设置目标，例如 `/goal Finish the migration and keep tests green`。
2.  输入 `/goal` 查看当前目标。
3.  使用 `/goal pause`、`/goal resume` 或 `/goal clear` 暂停、恢复或移除目标。

预期结果：Codex 会在工作继续推进时，把该目标持续附加到活动对话线程上。

目标内容必须非空，且最多 4,000 个字符。对于更长的指令，请把细节放进文件，并让目标指向该文件。

<span id="toggle-experimental-features-with-experimental"></span>

#### 用 `/experimental` 切换实验性功能

1.  输入 `/experimental` 并按 Enter。
2.  切换你想启用的功能，例如 Apps 或 Guardian approval；如果 Codex 提示需要重启，则按提示执行。

预期结果：Codex 会把你的功能选择写入配置，并在重启后生效。

<span id="approve-an-auto-review-denial-with-approve"></span>

#### 用 `/approve` 批准自动评审拒绝后的重试

当自动评审拒绝了最近一次动作，而你希望 Codex 重试一次时，可以使用 `/approve`。

1.  输入 `/approve`。
2.  当 Codex 显示相关被拒绝动作时，确认重试。

预期结果：Codex 会在当前会话策略下重试该被拒绝动作一次。

<span id="configure-memories-with-memories"></span>

#### 用 `/memories` 配置记忆

1.  输入 `/memories`。
2.  选择 Codex 应该使用已有记忆、生成新记忆，还是保持记忆行为关闭。

预期结果：Codex 会更新后续会话使用的相关记忆设置。

<span id="use-skills-with-skills"></span>

#### 用 `/skills` 使用技能

1.  输入 `/skills`。
2.  选择你希望 Codex 应用的技能。

预期结果：Codex 会插入所选技能上下文，让下一条请求遵循该技能的说明。

<span id="import-claude-code-configuration-with-import"></span>

#### 用 `/import` 导入 Claude Code 设置

1.  输入 `/import`。
2.  选择 **Claude Code**。
3.  选择要迁移的设置、项目文件或最近聊天。

预期结果：Codex 会打开外部智能体导入选择器，并把选中的受支持产物导入 Codex 配置和本地文件。session 发现范围包括最近 30 天内最多 50 个聊天。

`/import` 只能在本地 TUI session 中运行。任务运行中、远程 session 中，以及连接到本地 app-server daemon 时不可用。

桌面 App 工作流和支持的产物类型请参见[从其他智能体导入](/docs/import)。

<span id="clear-the-terminal-and-start-a-new-chat-with-clear"></span>

#### 用 `/clear` 清空终端并开始新聊天

1.  输入 `/clear` 并按 Enter。

预期结果：Codex 会清空终端、重置当前可见的对话记录，并在同一个 CLI 会话中启动一个全新的聊天。

若要在创建时为新对话命名，请运行 `/clear release prep`。

与 <kbd>Ctrl</kbd>+<kbd>L</kbd> 不同，`/clear` 会开启一个新对话。

<kbd>Ctrl</kbd>+<kbd>L</kbd> 只会清空终端显示，不会清空当前聊天。任务运行中时，这两个动作都会被禁用。

<span id="archive-the-current-session-with-archive"></span>

#### 用 `/archive` 归档当前 session

1.  输入 `/archive` 并按 Enter。
2.  确认你要归档当前 session 并退出 Codex。

预期结果：Codex 会归档当前 session，并关闭交互式 TUI。Codex 会继续在本地保存 session transcript；之后可用 `codex unarchive <SESSION>` 恢复。

任务运行中时，`/archive` 不可用。

<span id="delete-the-current-session-with-delete"></span>

#### 用 `/delete` 删除当前 session

1.  输入 `/delete` 并按 Enter。
2.  确认你要删除当前 session 并退出 Codex。

预期结果：Codex 会删除当前 session transcript，并关闭交互式 TUI。删除是永久性的，也会移除派生出的后代 sessions。

任务运行中或处于侧边会话时，`/delete` 不可用。

<span id="update-permissions-with-permissions"></span>

#### 用 `/permissions` 更新权限

1.  输入 `/permissions` 并按 Enter。
2.  选择与你当前风险偏好匹配的审批预设，例如无人值守运行时可选 `Auto`，想先审查改动时可选 `Read Only`。启用具名权限配置档案时，选择器也会显示已配置的自定义配置档案及其说明。

预期结果：Codex 会公布新的策略，后续动作都会遵守更新后的审批模式，直到你再次修改。

<span id="include-ide-context-with-ide"></span>

#### 用 `/ide` 包含 IDE 上下文

1.  输入 `/ide`。
2.  如果你想解释 Codex 应如何使用当前 IDE 选区或打开文件，可以追加可选行内文本。

预期结果：Codex 会把可用 IDE 上下文加入下一条提示词。

<span id="toggle-vim-mode-with-vim"></span>

#### 用 `/vim` 切换 Vim 模式

1.  输入 `/vim`。
2.  继续在输入框中编辑。

预期结果：Codex 会为当前会话切换输入框 Vim 模式。若要让新会话默认使用 Vim 模式，请在 `config.toml` 中设置 `tui.vim_mode_default = true`。

<span id="set-up-the-elevated-windows-sandbox-with-setup-default-sandbox"></span>

#### 用 `/setup-default-sandbox` 设置提权后的 Windows 沙箱

这个命令仅在 Windows 上 Codex 正使用功能受限的 restricted-token 沙箱时显示。

1.  输入 `/setup-default-sandbox`。
2.  按照管理员设置流程操作。

预期结果：Codex 会配置提权后的 Windows 沙箱，并选择相应的自动审批预设。

<span id="copy-the-latest-response-with-copy"></span>

#### 用 `/copy` 复制最新回复

1.  输入 `/copy` 并按 Enter。

预期结果：Codex 会把最近一条已完成的输出复制到剪贴板。

如果当前会话轮次仍在运行，`/copy` 会复制最近一条已完成的输出，而不是正在生成中的回复。在第一条完整输出产生之前，以及回滚刚结束后，这个命令不可用。

你也可以在主 TUI 中按 <kbd>Ctrl</kbd>+<kbd>O</kbd>，不打开斜杠命令菜单也能复制最近一次已完成回复。

<span id="toggle-raw-scrollback-with-raw"></span>

#### 用 `/raw` 切换原始滚动回看

1.  输入 `/raw`、`/raw on` 或 `/raw off`。

预期结果：Codex 会切换原始滚动回看（raw scrollback）模式，让终端选中和复制更直接。你也可以使用默认 <kbd>Alt</kbd>+<kbd>R</kbd> 绑定，或通过 `tui.raw_output_mode = true` 持久化默认值。

<span id="grant-sandbox-read-access-with-sandbox-add-read-dir"></span>

#### 用 `/sandbox-add-read-dir` 授予沙箱读权限

这个命令只在 Windows 原生 CLI 中可用。

1.  输入 `/sandbox-add-read-dir C:\absolute\directory\path` 并按 Enter。
2.  确认该路径是一个存在的绝对目录。

预期结果：Codex 会刷新 Windows 沙箱策略，并为后续在沙箱中运行的命令授予该目录的读权限。

<span id="inspect-the-session-with-status"></span>

#### 用 `/status` 查看当前会话

1.  在任意对话中输入 `/status`。
2.  查看输出中的当前模型、审批策略、可写根目录和 token 使用情况。TUI 远程连接时，输出还会显示远程地址和服务端版本。

预期结果：Codex 会打印摘要，用来确认它正在你预期的位置和配置下运行。

<span id="view-account-usage-with-usage"></span>

#### 用 `/usage` 查看账户用量

1.  输入 `/usage` 打开用量菜单。
2.  选择查看 token 活动，或使用可用的 earned reset。
3.  若要直接打开 token 活动视图，可以输入 `/usage daily`、`/usage weekly` 或 `/usage cumulative`。

预期结果：Codex 会打开用量动作，或展示所选视图下的账户 token 活动。如果当前 session 没有 Codex service account auth，Codex 会提示需要登录。

<span id="inspect-config-layers-with-debug-config"></span>

#### 用 `/debug-config` 查看配置层

1.  输入 `/debug-config`。
2.  查看输出中的配置层顺序、启用状态和策略来源。

预期结果：Codex 会打印各层配置诊断，以及策略细节，例如 `allowed_approval_policies`、`allowed_sandbox_modes`、`mcp_servers`、`rules`、`enforce_residency` 和 `experimental_network`（若已配置）。

当某个生效设置与你在 `config.toml` 中看到的不一致时，这份输出很适合拿来排查原因。

<span id="configure-footer-items-with-statusline"></span>

#### 用 `/statusline` 配置底部状态栏项目

1.  输入 `/statusline`。
2.  用选择器切换并重排项目，然后确认。

预期结果：底部状态栏会立刻更新，并把配置持久写入 `config.toml` 中的 `tui.status_line`。

可显示的状态栏项包括 model、model+reasoning、context 统计、rate limits、Git branch、token 计数、session id、当前目录 / 项目根，以及 Codex 版本。

<span id="configure-terminal-title-items-with-title"></span>

#### 用 `/title` 配置终端标题项

1.  输入 `/title`。
2.  用选择器切换并重排项目，然后确认。

预期结果：终端窗口或标签标题会立刻更新，并把配置持久写入 `config.toml` 中的 `tui.terminal_title`。

可显示的标题项包括 app 名称、项目、加载指示器、状态、对话线程、Git 分支、模型和任务进度。

<span id="choose-a-syntax-theme-with-theme"></span>

#### 用 `/theme` 选择语法主题

1.  输入 `/theme`。
2.  从选择器中预览主题，然后确认。

预期结果：Codex 会更新语法高亮，并把选择持久写入 `config.toml` 中的 `tui.theme`。

<span id="choose-a-terminal-pet-with-pets"></span>

#### 用 `/pets` 选择终端宠物

1.  输入 `/pets`（或 `/pet`）打开宠物选择器。
2.  选择内置或自定义宠物，也可以关闭宠物显示。

预期结果：Codex 会在支持的终端中显示所选环境宠物，并持久保存该选择。你也可以输入 `/pets off` 将其隐藏。

<span id="remap-tui-shortcuts-with-keymap"></span>

#### 用 `/keymap` 重新映射 TUI 快捷键

使用 `/keymap` 可以查看、更新并持久保存 TUI 的快捷键绑定。

1.  输入 `/keymap`。
2.  选择要修改的快捷键 context 和 action。
3.  输入新的绑定，或移除现有绑定。

预期结果：Codex 会更新当前 keymap，并把自定义绑定写入 `config.toml` 中的 `tui.keymap`。

快捷键绑定使用 `ctrl-a`、`shift-enter`、`page-down` 这类名称。特定上下文的绑定会覆盖 `tui.keymap.global`；空绑定列表表示解除该动作绑定。

<span id="check-background-terminals-with-ps"></span>

#### 用 `/ps` 查看后台终端

1.  输入 `/ps`。
2.  查看后台终端列表及其状态。

预期结果：Codex 会展示每个后台终端的命令，以及最多三行最近、非空输出，方便你快速判断进度。

只有在启用了 `unified_exec` 时才会出现后台终端；否则列表可能为空。

<span id="stop-background-terminals-with-stop"></span>

#### 用 `/stop` 停止后台终端

1.  输入 `/stop`。
2.  如果 Codex 在停止前要求确认，就按提示确认。

预期结果：Codex 会停止当前会话中的所有后台终端。`/clean` 仍可作为 `/stop` 的别名使用。

<span id="keep-transcripts-lean-with-compact"></span>

#### 用 `/compact` 精简对话记录

1.  在一次较长的对话后输入 `/compact`。
2.  当 Codex 提示是否要总结当前对话时，确认即可。

预期结果：Codex 会用一段简洁摘要替换较早的会话轮次，在保留关键细节的同时释放上下文。

<span id="review-changes-with-diff"></span>

#### 用 `/diff` 审查改动

1.  输入 `/diff` 查看 Git diff。
2.  在 CLI 内滚动输出，审查改动和新增文件。

预期结果：Codex 会显示已暂存的改动、未暂存的改动，以及 Git 尚未开始追踪的文件，帮助你决定要保留什么。

<span id="highlight-files-with-mention"></span>

#### 用 `/mention` 高亮文件

1.  输入 `/mention` 后跟路径，例如 `/mention src/lib/api.ts`。
2.  从弹出菜单中选择匹配结果。

预期结果：Codex 会把该文件加入当前对话，使后续会话轮次能直接引用它。

<span id="start-a-new-chat-with-new"></span>

#### 用 `/new` 开启新对话

1.  输入 `/new` 并按 Enter。

预期结果：Codex 会在同一个 CLI 会话中开启一个全新对话，让你无需退出终端就能切换到另一项任务。

若要在创建时为新对话命名，请运行 `/new bug bash`。

与 `/clear` 不同，`/new` 不会先清空当前终端显示。

<span id="rename-the-current-chat-with-rename"></span>

#### 用 `/rename` 重命名当前聊天

1.  输入 `/rename <name>`；也可以只输入 `/rename`，打开命名提示。
2.  输入一个便于日后找到该聊天的简短名称。

预期结果：Codex 会更新已保存的聊天名称，但不会更改 transcript。

<span id="resume-a-saved-chat-with-resume"></span>

#### 用 `/resume` 恢复已保存对话

1.  输入 `/resume` 并按 Enter。
2.  从保存的会话选择器中选中你要恢复的对话。

预期结果：Codex 会载入你所选对话的完整记录，让你从原来的进度继续，而不会丢掉历史内容。

<span id="fork-the-current-chat-with-fork"></span>

#### 用 `/fork` 分叉当前对话

1.  输入 `/fork` 并按 Enter。

预期结果：Codex 会把当前对话复制成一个带有新 ID 的对话线程，原始对话记录保持不变，因此你可以并行探索另一种方案。

如果你要 fork 的不是当前对话，而是某个已保存 session，请在终端中运行 `codex fork`，打开 session picker。

<span id="continue-in-the-desktop-app-with-app"></span>

#### 用 `/app` 在桌面 App 中继续

在 macOS 和 Windows 上，输入 `/app` 可在 ChatGPT 桌面 App 中打开当前 session。如果 App 尚未安装或没有运行，Codex 会显示错误，提示你安装或启动它。

预期结果：桌面 App 会打开同一个已保存的聊天，你可以在那里继续。

<span id="start-a-side-chat-with-side"></span>

#### 用 `/side` 启动侧边会话（side conversation）

使用 `/side` 可以从当前对话启动一个临时分叉，而不离开主任务。

1.  输入 `/side` 打开侧边会话。
2.  也可以附带行内文本，例如 `/side Check whether this plan has an obvious risk`。
3.  这个聚焦插曲结束后，返回父对话线程。

预期结果：Codex 会打开一个转录记录与父对话线程分离的侧边会话。处于侧边模式时，TUI 仍会显示父对话线程状态，方便你确认主任务是否仍在运行。

`/side` 不能在另一个侧边会话内使用，也不能在评审模式中使用。

<span id="generate-agentsmd-with-init"></span>

#### 用 `/init` 生成 `AGENTS.md`

1.  在你希望 Codex 查找长期指令的目录中运行 `/init`。
2.  查看生成的 `AGENTS.md`，再按仓库约定继续编辑。

预期结果：Codex 会创建一个可继续完善并提交、供后续会话使用的 `AGENTS.md` 骨架。

<span id="ask-for-a-working-tree-review-with-review"></span>

#### 用 `/review` 审查工作树

1.  输入 `/review`。
2.  如果你还想查看精确的文件改动，可继续运行 `/diff`。

预期结果：Codex 会总结它在当前工作树中发现的问题，重点关注行为变化与缺失测试。默认使用当前 session 的 model，除非你在 `config.toml` 中单独设置了 `review_model`。

<span id="list-mcp-tools-with-mcp"></span>

#### 用 `/mcp` 列出 MCP 工具

1.  输入 `/mcp`。
2.  查看列表，确认当前有哪些 MCP server 和工具可用。

预期结果：你会看到当前会话中 Codex 可调用的 MCP 工具列表。

使用 `/mcp verbose` 可以包含详细的服务端诊断信息。如果传入的参数不是 `verbose`，Codex 会显示命令用法。

<span id="browse-apps-with-apps"></span>

#### 用 `/apps` 浏览 Apps

1.  输入 `/apps`。

预期结果：Codex 会把 App mention 以 `$app-slug` 的形式插入输入框，这样你就可以立刻要求 Codex 调用它。

<span id="browse-plugins-with-plugins"></span>

#### 用 `/plugins` 浏览插件

预期结果：Codex 会打开插件浏览器，让你查看已安装插件、当前配置允许发现的插件，以及已安装插件状态。在已安装插件上按 <kbd>Space</kbd> 可以切换它的启用状态。

<span id="view-and-manage-lifecycle-hooks-with-hooks"></span>

#### 用 `/hooks` 查看和管理生命周期 hooks

1.  输入 `/hooks`。
2.  查看当前会话中已加载的生命周期 hook 配置。

预期结果：Codex 会显示当前会话可运行的 hooks。

<span id="switch-agent-threads-with-agent"></span>

#### 用 `/agent` 切换智能体对话线程
