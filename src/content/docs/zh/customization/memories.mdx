记忆让 ChatGPT 和 Codex 可以把先前工作中的有用上下文带入后续工作。ChatGPT Web 使用 ChatGPT memory（记忆功能）；本地 Codex 客户端则使用一套独立的本地记忆存储和控制方式。

团队必须遵守的指导应保存在 `AGENTS.md` 或已提交到仓库的文档中。记忆只是一层辅助回忆机制，不应成为必须始终生效的规则的唯一来源。

在 ChatGPT 桌面应用中，使用 `/memories` 决定当前聊天能否使用本地记忆，以及该聊天能否用于生成后续记忆。需要全局开启或关闭时，前往 **Settings > Personalization（设置 > 个性化）**。

[Chronicle](/docs/customization/chronicle) 是桌面端专属功能，可以帮助 Codex 从屏幕活动中恢复最近的工作上下文并建立记忆。

<span id="how-memories-work"></span>

## 本地 Codex 记忆如何工作

启用记忆后，Codex 可以把符合条件的旧聊天中的有用上下文写入本地记忆文件。Codex 会跳过仍在进行或生命周期很短的 session，对生成的记忆字段进行秘密信息脱敏，并在后台更新记忆，而不是在每个聊天结束时立即处理。

聊天结束后，记忆可能不会立刻更新。Codex 会等待聊天空闲足够长的时间，避免在工作仍在继续时过早总结。

当 Codex 剩余速率限制百分比低于配置阈值时，后台记忆生成也可能跳过，以免在额度接近上限时继续消耗配额。

## 本地记忆存储

Codex 把记忆保存在 Codex home 目录下，默认位置是 `~/.codex`。Codex 如何使用 `CODEX_HOME`，请参阅[配置和状态位置](/docs/config-file/config-advanced#config-and-state-locations)。

主要记忆文件位于 `~/.codex/memories/`，其中包括摘要、持久条目、最近输入，以及来自旧聊天的支持证据。

这些文件属于生成状态。排查问题或分享 Codex home 目录前可以检查它们，但不要把手工编辑这些文件作为主要控制方式。

<span id="control-local-memories-per-task"></span>

## 按聊天控制本地记忆

在 ChatGPT 桌面应用和 Codex TUI 中，使用 `/memories` 控制当前聊天的记忆行为。聊天级选项可以决定当前聊天能否使用现有记忆，以及 Codex 能否把该聊天用于生成未来记忆。

聊天级选择不会改变你的全局记忆设置。

## 检查本地记忆

不要在记忆中保存秘密信息。Codex 会从生成的记忆字段中脱敏秘密信息，但在分享 Codex home 目录或生成的记忆产物前，仍应检查相关文件。

<span id="enable-memories"></span>

## 配置本地记忆

本地 Codex 记忆默认关闭。在 ChatGPT 桌面应用中打开 **Settings > Personalization（设置 > 个性化）**，启用 **Enable memories（启用记忆）**。

如果通过配置文件启用，请在 `config.toml` 中加入功能开关：

<CodeBlock code={"[features]\nmemories = true"} language="toml" />

配置文件位置及完整记忆设置请参阅[配置基础](/docs/config-file/config-basic)和[配置参考](/docs/config-file/config-reference)。常用设置包括：

-   `memories.generate_memories`：控制新建聊天能否成为记忆生成输入。
-   `memories.use_memories`：控制 Codex 是否向后续会话注入已有记忆。
-   `memories.disable_on_external_context`：设为 `true` 时，不会把使用过 MCP 工具调用、Web 搜索或工具搜索等外部上下文的聊天用于生成记忆。旧键 `memories.no_memories_if_mcp_or_web_search` 仍可作为别名使用。
-   `memories.min_rate_limit_remaining_percent`：开始生成记忆所需的最低 Codex 剩余额度百分比。
-   `memories.extract_model`：覆盖每个聊天执行记忆提取时使用的模型。
-   `memories.consolidation_model`：覆盖执行全局记忆合并时使用的模型。
