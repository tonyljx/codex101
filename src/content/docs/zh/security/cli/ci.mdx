在 CI 中运行 Codex Security CLI 以查看 pull request 中的确切更改，保留结果和覆盖范围，并可选择在选定的严重性下使检查失败。从咨询结果开始，检查扫描质量和运行时间，然后添加适合你的仓库的严重性策略。

<Callout kind="note">

安装公开发布的 `@openai/codex-security` 软件包。运行扫描仍需获得 Codex Security 访问权限。

</Callout>

本指南使用 GitHub Actions。相同的扫描和导出命令适用于其他 CI 系统。

## 准备工作流

将 OpenAI API key 存储为名为 `CODEX_SECURITY_API_KEY` 的仓库或组织机密。

将此 secret 直接映射到扫描步骤的 `OPENAI_API_KEY` 环境变量。只在扫描进程中提供该凭据，并使用 `--auth api-key` 显式选择它。

runner 需要：

-   Node.js 22 或更高版本。
-   Python 3.10 或更高版本。
-   公开发布的 `@openai/codex-security` 软件包；将其安装在仓库 checkout 之外。
-   pull request 的 head 与 base 历史记录，以便 Git 计算 merge base。
-   当你上传 SARIF 时，为私有或内部仓库启用 [GitHub 代码安全](https://docs.github.com/en/code-security/code-scanning/integrating-with-code-scanning/uploading-a-sarif-file-to-github)。

## 添加 GitHub Actions 工作流

创建 `.github/workflows/codex-security.yml`。在 checkout pull request 之前，在 `$RUNNER_TEMP/codex-security` 下安装 `@openai/codex-security@0.1.3`，使受信任的可执行文件位于 `$RUNNER_TEMP/codex-security/node_modules/.bin/codex-security`：

<CodeBlock code={"name: Codex Security scan\n\non:\n  pull_request:\n\njobs:\n  codex-security:\n    if: github.event.pull_request.head.repo.full_name == github.repository && github.actor != 'dependabot[bot]'\n    runs-on: ubuntu-latest\n    permissions:\n      actions: read\n      contents: read\n      security-events: write\n    steps:\n      - name: Set up Node.js\n        uses: actions/setup-node@820762786026740c76f36085b0efc47a31fe5020 # v7\n        with:\n          node-version: \"26\"\n\n      - name: Set up Python\n        uses: actions/setup-python@5fda3b95a4ea91299a34e894583c3862153e4b97 # v7\n        with:\n          python-version: \"3.14\"\n\n      - name: Install Codex Security\n        run: |\n          set -euo pipefail\n          npm install \\\n            --prefix \"$RUNNER_TEMP/codex-security\" \\\n            --ignore-scripts \\\n            --no-audit \\\n            --no-fund \\\n            @openai/codex-security@0.1.3\n\n      - name: Verify Codex Security\n        env:\n          CODEX_SECURITY_BIN: ${{ runner.temp }}/codex-security/node_modules/.bin/codex-security\n        run: |\n          set -euo pipefail\n          test -x \"$CODEX_SECURITY_BIN\"\n          \"$CODEX_SECURITY_BIN\" --version\n\n      - name: Check out the pull request\n        uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7\n        with:\n          ref: ${{ github.event.pull_request.head.sha }}\n          fetch-depth: 0\n          persist-credentials: false\n\n      - name: Scan the pull request\n        env:\n          OPENAI_API_KEY: ${{ secrets.CODEX_SECURITY_API_KEY }}\n          CODEX_SECURITY_BIN: ${{ runner.temp }}/codex-security/node_modules/.bin/codex-security\n          CODEX_SECURITY_STATE_DIR: ${{ runner.temp }}/codex-security-state\n          BASE_SHA: ${{ github.event.pull_request.base.sha }}\n          HEAD_SHA: ${{ github.event.pull_request.head.sha }}\n          SCAN_DIR: ${{ runner.temp }}/codex-security-results\n        run: |\n          set -euo pipefail\n          BASE_REVISION=\"$(git merge-base \"$BASE_SHA\" \"$HEAD_SHA\")\"\n          \"$CODEX_SECURITY_BIN\" scan . \\\n            --diff \"$BASE_REVISION\" \\\n            --head \"$HEAD_SHA\" \\\n            --auth api-key \\\n            --output-dir \"$SCAN_DIR\" \\\n            --json > \"$RUNNER_TEMP/codex-security.json\"\n\n      - name: Export SARIF\n        id: export-sarif\n        if: always()\n        env:\n          CODEX_SECURITY_BIN: ${{ runner.temp }}/codex-security/node_modules/.bin/codex-security\n          SCAN_DIR: ${{ runner.temp }}/codex-security-results\n          SARIF_FILE: ${{ runner.temp }}/codex-security.sarif\n        run: |\n          set -euo pipefail\n          if test -f \"$SCAN_DIR/scan-manifest.json\"; then\n            \"$CODEX_SECURITY_BIN\" export \"$SCAN_DIR\" \\\n              --export-format sarif \\\n              --source-root \"$GITHUB_WORKSPACE\" \\\n              --output \"$SARIF_FILE\"\n            echo \"available=true\" >> \"$GITHUB_OUTPUT\"\n          fi\n\n      - name: Upload SARIF\n        if: always() && steps.export-sarif.outputs.available == 'true'\n        uses: github/codeql-action/upload-sarif@e4fba868fa4b1b91e1fdab776edc8cfbe6e9fb81 # v4\n        with:\n          sarif_file: ${{ runner.temp }}/codex-security.sarif\n          ref: refs/pull/${{ github.event.pull_request.number }}/head\n          sha: ${{ github.event.pull_request.head.sha }}\n          category: codex-security\n\n      - name: Preserve scan results\n        if: always()\n        uses: actions/upload-artifact@043fb46d1a93c77aae656e7c1c64a875d1fc6a0a # v7\n        with:\n          name: codex-security-results\n          path: |\n            ${{ runner.temp }}/codex-security-results\n            ${{ runner.temp }}/codex-security.json\n          if-no-files-found: warn\n          retention-days: 7"} language="yaml" />

工作流会检出 pull request 的 head，计算 merge base，并扫描这些 revision 之间已提交的变更。完整历史记录可确保目标准确。`persist-credentials: false` 可避免把仓库 token 写入 checkout 目录的 Git 配置。在 checkout 仓库前安装 CLI，并通过绝对路径运行，可防止仓库控制的可执行文件接触扫描凭据。`--auth api-key` 会显式选择作用域受限的 API key；扫描历史记录则保存在仓库之外的可写状态目录中。

`--json` 将一份完整的 JSON 文档写入 stdout，因此工作流可以直接保存它。进度、完成摘要和错误保留在 stderr 上。这与 `codex exec --json` 不同，后者发出 JSON Lines 事件流。

导出步骤读取已完成的已封存的扫描并写入 SARIF。它使 Codex 运行时和凭证保持不变。扫描产物可能包含易受攻击的源代码片段、证据和补救详细信息。选择适合你的仓库的访问控制和较短的保留窗口。

## 选择严重性策略

上述工作流仅报告，因为它省略了 `--fail-on-severity`。一旦你准备好让安全发现影响检查，请向扫描命令添加阈值：

<CodeBlock code={"\"$CODEX_SECURITY_BIN\" scan . \\\n  --diff origin/main \\\n  --output-dir /path/outside/repository/results \\\n  --fail-on-severity high"} language="bash" />

支持的阈值包括 `critical`、`high`、`medium` 和 `low`。阈值包括该严重程度及以上的安全发现。

扫描步骤使用这些退出码：

<div className="doc-table-wrap">

| 退出 | 意义 |
| --- | --- |
| `0` | 扫描完成并完全覆盖，并且所有配置的策略均已通过。 |
| `1` | 完成的扫描包含等于或高于阈值的结果。 |
| `2` | CLI 发现输入或运行时错误，或者已完成的扫描覆盖不完整。 |
| `130` | Ctrl-C 中断扫描。 |
| `143` | SIGTERM 终止扫描。 |

</div>

即使没有严重性策略，具有 `partial` 或 `unknown` 覆盖范围的扫描也会返回 `2`。CLI 仍然写下其可用的安全发现和报告。在将检查视为结论性检查之前，请检查 `coverage.json` 中的延后处理的范围。

## 使用现有结果目录重试

为每个 CI 作业使用新的运行器目录。对于持久或自托管运行器，请使用 `--archive-existing` 保留早期结果：

<CodeBlock code={"\"$CODEX_SECURITY_BIN\" scan . \\\n  --diff origin/main \\\n  --output-dir /path/outside/repository/results \\\n  --archive-existing"} language="bash" />

该命令存档早期的结果并从空扫描目录开始。

## 对 CI 扫描进行故障排除

-   **未知的 Git revision 或意外差异：** 获取 base 与 head 历史记录，计算 merge base，并显式传入两个 revision。
-   **受保护或非空输出目录：** 选择外层 Git 工作树之外的私有目录。当目录已包含结果时使用 `--archive-existing`。
-   **缺少凭据：** 确认 `CODEX_SECURITY_API_KEY` 仓库 secret 可用于受信任的工作流，并直接映射到扫描步骤的 `OPENAI_API_KEY` 环境变量。
-   **扫描历史记录错误：** 将 `CODEX_SECURITY_STATE_DIR` 设置为仓库之外的可写目录。
-   **Python 设置错误：** 确认运行器使用 Python 3.10 或更高版本。
-   **覆盖不完整：** 查看 `coverage.json` 中延后处理的范围和未解决的问题，然后使用适当的目标或环境重新运行。
-   **SARIF 导出错误：** 确认扫描已完成且完整扫描目录可用。导出在写入 SARIF 之前验证已封存的产物。
-   **SARIF 上传错误：** 对于私有或内部仓库，请确认你的组织已为仓库打开 GitHub 代码安全性，并且工作流授予 `actions: read`、`contents: read` 和 `security-events: write`。

要查看每个命令、flag、产物和输出字段，请参阅 [CLI 参考](/docs/security/cli/reference)。有关基于交互式插件的 CI 评审，请参阅[评审代码变更中的安全风险](/docs/security/plugin/code-changes#automate-reviews-in-cicd)。
