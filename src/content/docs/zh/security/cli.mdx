Codex Security 帮助安全和工程团队发现、确认并修复漏洞。你可以使用命令行界面（CLI）扫描自己拥有或获准评估的仓库，持续评审安全发现，并在变更落地前检查相关风险。

<Callout kind="note">

`@openai/codex-security` 软件包已公开发布。运行扫描仍需获得 Codex Security 访问权限。要在 Codex 中进行交互式扫描，请从 [Codex Security 插件快速入门](/docs/security/plugin)开始。对于已连接的 GitHub 仓库，请参阅 [Codex Security 云端设置](/docs/security/setup)。

</Callout>

## 检查先决条件

CLI 需要 Node.js 22 或更高版本。运行扫描或导出结果还需要 Python 3.10 或更高版本。有关更多详细信息，请参阅[认证和先决条件](/docs/security/cli/reference#authentication-and-prerequisites)。

## 设置并验证 CLI

安装公开发布的软件包：

<CodeBlock code={"npm install @openai/codex-security"} language="bash" />

检查已安装的版本：

<CodeBlock code={"npx @openai/codex-security --version"} language="bash" />

列出可用的命令：

<CodeBlock code={"npx @openai/codex-security --help"} language="bash" />

使用 `npx @openai/codex-security scan --help` 或 `npx @openai/codex-security export --help` 获取完整的命令帮助。 [CLI 参考](/docs/security/cli/reference) 涵盖了每个参数、输出格式和退出码。

## 登录

对于本地使用，请使用你的 ChatGPT 账号登录：

<CodeBlock code={"npx @openai/codex-security login"} language="bash" />

在远程或无头计算机上，使用设备认证：

<CodeBlock code={"npx @openai/codex-security login --device-auth"} language="bash" />

对于 CI 和其他自动化工作流，请改用 OpenAI API key：

<CodeBlock code={"export OPENAI_API_KEY=\"<your-api-key>\""} language="bash" />

将 API key 保存在 shell 环境或 secret manager 中。Codex Security 也可以复用现有的文件式 Codex 登录。

如果已保存的 ChatGPT 登录与环境中的 API key 同时可用，使用文本输出的交互式扫描会询问要使用哪一种。CI、JSON 和 JSONL 扫描以及其它无人值守扫描默认使用 API key。

如需使用已存储的登录凭据，请传入 `--auth chatgpt`：

<CodeBlock code={"npx @openai/codex-security scan . --auth chatgpt"} language="bash" />

要强制使用环境变量中的 API key，请显式选择 API key 认证：

<CodeBlock code={"npx @openai/codex-security scan . --auth api-key"} language="bash" />

如需让已存储的登录凭据成为自动选择的默认值，请取消设置两个环境变量：

<CodeBlock code={"unset OPENAI_API_KEY CODEX_API_KEY"} language="bash" />

根据你的账号和仓库，完整仓库扫描可能还需要 [Trusted Access for Cyber](https://chatgpt.com/cyber)。登录或设置 API key 不会授予该访问权限。

## 准备扫描

选择要扫描的仓库和要写入结果的目录。

<CodeBlock code={"REPOSITORY=/path/to/repository\nSCAN_DIR=/path/outside/repository/codex-security-results"} language="bash" />

如果省略 `--output-dir`，Codex Security 会将结果保存在其自己的持久状态目录中。结果可以包括源代码摘录和漏洞详细信息，因此请选择私有位置和适当的保留策略。

如果默认状态目录不可写，请选择扫描仓库之外的可写目录：

<CodeBlock code={"export CODEX_SECURITY_STATE_DIR=/path/outside/repository/codex-security-state"} language="bash" />

在开始扫描之前检查仓库、目标和输出目录：

<CodeBlock code={"npx @openai/codex-security scan \"$REPOSITORY\" --output-dir \"$SCAN_DIR\" --dry-run"} language="bash" />

试运行会检查本地输入，而无需启动 Codex、加载凭据或探测插件的 Python 解释器。

## 运行你的第一次扫描

运行标准扫描并将其结果保存在选定的目录中：

<CodeBlock code={"npx @openai/codex-security scan \"$REPOSITORY\" --output-dir \"$SCAN_DIR\""} language="bash" />

默认情况下，CLI 会将扫描进度和完成摘要写入 stderr，而不会把完整扫描结果写入 stdout。完成的扫描会打印如下摘要：

<CodeBlock code={"codex-security: Findings: 2 (1 high, 1 medium). Coverage: complete.\ncodex-security: Elapsed: 42s.\ncodex-security: Report: /path/outside/repository/codex-security-results/report.md\ncodex-security: Results: /path/outside/repository/codex-security-results"} language="text" />

如果要把完整结果作为机器可读的 JSON 输出，请显式请求结构化输出：

<CodeBlock code={"npx @openai/codex-security scan \"$REPOSITORY\" --output-dir \"$SCAN_DIR\" --json"} language="bash" />

默认情况下，扫描只生成报告，结果会留在本地供你评审。准备好[在 CI 中运行扫描](/docs/security/cli/ci) 后，可以再添加严重性阈值。

## 选择模型和推理强度

扫描默认使用 `gpt-5.6-sol` 和 `xhigh` 推理强度。任务需要其它配置时，可以选择不同的模型和推理强度：

<CodeBlock code={"npx @openai/codex-security scan \"$REPOSITORY\" \\\n  --model gpt-5.6-terra \\\n  --effort high"} language="bash" />

支持的推理强度为 `minimal`、`low`、`medium`、`high` 和 `xhigh`。

## 查看结果

打开 `report.md` 即可得到可读结果。扫描目录还包含自动化使用的结构化文件：

<CodeBlock code={"codex-security-results/\n├── scan-manifest.json\n├── findings.json\n├── coverage.json\n├── report.md\n├── artifacts/\n└── exports/\n    └── results.sarif       # when produced"} language="text" />

-   `scan-manifest.json` 记录目标、范围、生产者和已封存的产物。
-   `findings.json` 记录每项安全发现的严重性、置信度、位置、证据和补救措施。
-   `coverage.json` 记录已评审范围、排除、延后处理的工作、未解决的问题和覆盖范围的完整性。

覆盖范围可以是 `complete`、`partial` 或 `unknown`。在将扫描视为评审证据之前，请阅读任何延后处理的范围或未解决的问题。 [CLI 参考](/docs/security/cli/reference#scan-artifacts) 描述了完整的产物和输出合约。

## 选择下一次扫描

当仓库包含单独的服务或包时，使用路径扫描：

<CodeBlock code={"npx @openai/codex-security scan \"$REPOSITORY\" --path services/billing --path packages/auth"} language="bash" />

查看基础修订版和 `HEAD` 之间已提交的更改：

<CodeBlock code={"npx @openai/codex-security scan \"$REPOSITORY\" --diff origin/main --head HEAD"} language="bash" />

针对 `HEAD` 检查已暂存和未暂存的更改：

<CodeBlock code={"npx @openai/codex-security scan \"$REPOSITORY\" --working-tree --base HEAD"} language="bash" />

差异和工作树扫描期望仓库参数是 Git 工作树根。在开始差异扫描之前获取选定的修订版本。

当仓库或路径需要更广泛的评审时，请使用深度模式：

<CodeBlock code={"npx @openai/codex-security scan \"$REPOSITORY\" --mode deep"} language="bash" />

深度模式支持仓库和路径目标，不支持 diff 或工作树扫描。

## 添加架构和安全上下文

提供架构文档、威胁模型或安全策略作为扫描上下文。这有助于 Codex Security 根据系统的实际工作方式评估结果：

<CodeBlock code={"npx @openai/codex-security scan \"$REPOSITORY\" \\\n  --knowledge-base /path/to/architecture.md \\\n  --knowledge-base /path/to/security-policies"} language="bash" />

## 设置扫描预算

当估计模型成本超过美元限制时，使用 `--max-cost` 停止扫描：

<CodeBlock code={"npx @openai/codex-security scan \"$REPOSITORY\" --max-cost 5"} language="bash" />

已在处理的请求可能会超出限制。Codex Security 在扫描停止时保留可用结果。

## 每次提交前扫描更改

为你的仓库安装 Git 预提交安全检查：

<CodeBlock code={"npx @openai/codex-security install-hook"} language="bash" />

该检查会在每次提交前扫描已暂存和未暂存的更改。它可以阻止高严重性安全发现和扫描错误，且不会替换现有的 pre-commit 脚本。

## 批量扫描仓库

在发现仓库之前登录 GitHub：

<CodeBlock code={"gh auth login"} language="bash" />

从你的 GitHub 账号或组织中发现并选择仓库：

<CodeBlock code={"npx @openai/codex-security bulk-scan"} language="bash" />

交互流程不会列出已归档仓库和 fork，并会要求你在扫描前确认所选仓库。

要扫描准备好的仓库列表，请提供 CSV 和输出目录：

<CodeBlock code={"npx @openai/codex-security bulk-scan repositories.csv \\\n  --output-dir /path/outside/repositories/security-scans \\\n  --workers 4"} language="bash" />

再次运行同一命令即可恢复现有批量扫描。已经完成且结果产物完整的仓库不会被重复扫描。需要重试临时的仓库检出错误或扫描错误时，请添加 `--max-attempts 3`。

有关 GitHub 发现、CSV 准备、批量扫描结果和 Docker 设置，请参阅[运行批量安全扫描](/docs/security/cli/bulk-scans)。

## 在 Docker 中运行批量扫描

如果你的访问权限包含 Codex Security Docker 镜像，请在 Linux Docker 主机上使用提供的加固版 Compose 配置和安全配置文件。主机必须支持创建非特权用户命名空间。准备仓库 CSV，将结果和登录状态保存在持久挂载目录中，并通过环境变量或 secret manager 提供凭据：

<CodeBlock code={"docker compose run --rm codex-security \\\n  bulk-scan /input/repositories.csv \\\n  --output-dir /output \\\n  --workers 4"} language="bash" />

容器会以非交互方式运行批量扫描。如需交互式发现仓库，请在 Docker 外部使用 CLI。对于私有仓库，请通过环境变量或 secret manager 提供 `GH_TOKEN` 或 `GITHUB_TOKEN`。[登录要求](#%E7%99%BB%E5%BD%95)（包括账号和仓库访问权限）同样适用于容器化扫描。

## 重新访问保存的扫描

列出仓库中保存的扫描：

<CodeBlock code={"npx @openai/codex-security scans list \"$REPOSITORY\""} language="bash" />

从结果中复制扫描 ID 以检查其结果和配置：

<CodeBlock code={"npx @openai/codex-security scans show SCAN_ID"} language="bash" />

要把已评审的安全发现标记为误报，请说明为什么该发现不适用：

<CodeBlock code={"npx @openai/codex-security findings false-positive FINDING_OCCURRENCE_ID \\\n  --reason \"The route already checks permissions\""} language="bash" />

后续扫描会参考这项说明，但仍会重新检查当前代码。

使用原始配置针对当前检出内容重新运行同一扫描：

<CodeBlock code={"npx @openai/codex-security scans rerun SCAN_ID"} language="bash" />

要比较两次扫描，首先匹配具有相同根本原因的结果：

<CodeBlock code={"npx @openai/codex-security scans match PREVIOUS_SCAN_ID CURRENT_SCAN_ID"} language="bash" />

然后检查哪些结果是新的、持续存在的、重新打开的、已解决的或未知的：

<CodeBlock code={"npx @openai/codex-security scans compare PREVIOUS_SCAN_ID CURRENT_SCAN_ID"} language="bash" />

有关批量扫描 CSV 格式、扫描历史过滤器和命令选项，请参阅 [CLI 参考](/docs/security/cli/reference)。
